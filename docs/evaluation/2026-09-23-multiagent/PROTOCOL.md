# MyCapture 멀티에이전트 평가 절차

시작 시각(UTC): 2026-09-23T14:33:56Z
대상 커밋: `117b0ef` Release 3.0.0 (`main`)
최소 분석 시간: 3시간. 합의문은 시작 시각으로부터 3시간이 지나고, 라운드 1 독립 평가와 라운드 2 교차 합의가 끝난 뒤에만 확정한다.

이 평가는 홍보 문구가 아니다. 코드·테스트·XAML·공개 경쟁 문서만 근거로 삼는다. `docs/market/`는 0.x 보관 스냅샷이므로 현재 사실로 인용하지 않는다. 현재 경쟁 기준의 초안은 `docs/competitive-matrix.md`이나, 구현 여부는 코드를 다시 확인한다.

## 공통 규칙

- 제품 소스, 테스트, 릴리스 노트는 수정하지 않는다. 자기 산출물과 `inbox/<id>.md`만 쓴다.
- 점수는 1~5. 5는 이 제품의 목표(로컬 캡처 → 설명 → GIF/MP4) 안에서 경쟁 상위권, 3은 핵심은 되나 체감 공백, 1은 위험하거나 사실상 부재.
- 모든 감점·가점에는 저장소 경로를 붙인다. 확인하지 못한 내용은 "미확인"으로 남긴다.
- 경쟁 비교는 네 칸으로 나눈다.
  - **경쟁 우위**: 경쟁 제품이 더 잘하고 MyCapture에 없거나 약한 것
  - **과제 고유 강점**: 이 제품의 범위(무계정, 로컬 OCR, 핀, 비파괴 주석, 오디오 없는 설명용 녹화) 안에서만 성립하는 강점
  - **공통 약점**: 범용 캡처 도구도 같이 겪는 문제
  - **범위 밖**: OBS급 스트리밍·오디오처럼 의도적으로 목표에서 뺀 것. 감점하지 말고 범위 밖으로 분리한다.
- 다른 축과 겹칠 주장에는 `OVERLAP` 표시와 예상 상대 축을 붙인다. 같은 사실을 두 축의 감점으로 이중 계산하지 않도록, 어느 축이 주 소유자인지도 제안한다.

## 에이전트 소통

라운드 1은 독립이다. 다른 페르소나의 산출물을 읽지 않는다.
라운드 2에서만 전원의 라운드 1을 읽고, `round2/<id>.md`에 겹친 주장마다 `합의` / `병합` / `반박`을 적는다. 반박은 코드 근거가 있을 때만 한다. 주 소유자가 합의되면 보조 축은 그 주장을 반복 채점하지 않는다.

## 경쟁 제품 (직접 비교)

Snipaste, ShareX, Greenshot, 알캡처, PicPick, ScreenToGif, Windows 11 캡처 도구. OBS는 범위 밖 참조. 가격·광고는 이번 세션에서 연 공식 페이지가 있을 때만 적는다.
