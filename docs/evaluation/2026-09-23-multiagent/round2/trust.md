합산 **3**, 로컬 프라이버시 **4**, 배포 신뢰 **2**는 라운드 1에서 이미 반영된 신뢰 축 점수다. 아래 사실이 다른 축의 감점으로 한 번 더 들어가면 같은 코드가 두 번 깎인다. 다른 축은 이 세 숫자를 다시 산출하지 않는다.

| 점수 | 값 | 이 값에 이미 들어 있는 사실 | 주 소유 | 다른 축 |
|---|---:|---|---|---|
| 합산 | 3 | 로컬 캡처의 핵심은 성립하고, 게시자 증명과 로컬 평문 보존이 체감 공백이다. 두 부분점수의 산술 평균이 아니다. | trust | 신뢰 축 점수로 이 3만 쓴다. |

## 3. CL-09 — 완전 오프라인 문장

**답: positioning이 “완전 오프라인” 문장을 좁혀야 한다.** 좁히는 일은 포지션 문장의 위생이다. positioning의 일관성 점수, trust의 합산 3·로컬 4를 이 문장 때문에 다시 깎지 않는다.

라운드 1 positioning의 한 문장(“계정 없이 PC 안에서…”)에는 “완전 오프라인”이 없다. 좁힐 대상은 그 문장이 설치 절과 붙었을 때 무네트워크 실행으로 읽히는 자리다. `README.md` 설치 절은 self-contained라 “실행 중 인터넷 연결도 요구하지 않습니다”라고 적는다. `docs/market/`의 “완전 오프라인”은 보관 스냅샷이라 현재 점수의 근거가 아니다.

프로세스가 뜨면 모델 수신이 켜져 있다. `App.xaml.cs`가 셸 초기화에서 `StartOcrModelDownload()`를 호출하고, `OcrModelStore.EnsureAsync`가 파일이 없을 때 `OcrModelCatalog.cs`의 `https://www.modelscope.cn/...` 로 가중치를 받는다. 주석은 다운로드만 한다고 적는다. 캡처 픽셀과 OCR 문자열은 그 요청에 실리지 않는다. 실패해도 트레이는 남고 기본 품질은 `Windows.Media.Ocr`이다. Real-ESRGAN은 Enhanced의 첫 인식에서만 받는다 (`round1/06-trust.md` 네트워크 표면, `NeuralOcrEngine`).

그래서 positioning이 유지할 문장과 빼야 할 문장은 아래다.

| 문장 | positioning이 할 일 |
|---|---|
| self-contained, .NET 선설치 불필요, 오디오·텔레메트리·FFmpeg 번들 부재 (POS-02) | 유지. 구현이 문장을 받친다. OBS 오디오·스트리밍은 범위 밖. |
| 캡처와 기본(Fast) OCR은 받은 모델 없이도 끝난다 | 유지. 기본 경로는 `Windows.Media.Ocr`. |
| 첫 실행이 PP-OCR 가중치를 받으려 하며, 이미 있으면 요청하지 않는다 | 포지션 문장에 기본 켜짐으로 적는다. 채점은 trust의 네트워크 표면. |
| GitHub 단축키와 설정 속 업데이트 확인은 사용자가 누를 때만 네트워크로 나간다 | 로컬 설명 문장 밖의 목적지로 둔다 (POS-06의 범위). 전송 안전은 trust. |
| “완전 오프라인”, “항상 오프라인”, 실행 중 인터넷을 전혀 쓰지 않는다는 읽기 | 포지션 문장에서 뺀다. |

### 네트워크 표면 (라운드 1 요약, 재채점 아님)

| 출구 | 기본 | 올라가는 것 | 소유 |
|---|---|---|---|
| 제품 분석·크래시 텔레메트리 | 없음 | 없음 | trust가 부재를 확인 (T01). positioning은 그 부재를 범위 문장으로 인용 (POS-02). |

## 4. CL-08 — Authenticode

**합의.** 배포 신뢰 2의 주 소유는 trust다.

| 주장 | 근거 | 처리 |
|---|---|---|
| T16, 라운드 1 배포 신뢰 2 | `SECURITY.md`는 Authenticode가 없고 체크섬이 게시자 신원이 아니라고 적는다. `README.md` 서명 문단이 같다. `build/package.ps1`은 `Unsigned = $true`. | trust가 감점한 전부. 배포 2를 유지. |
| LRN-17 | 설치 UI가 미서명 경고의 다음 행동을 설명하지 않는다. `install.ps1`에 Authenticode 안내가 없다. | 학습성은 그 설명 공백만 소유한다. 서명 부재로 학습성 점수를 깎지 않는다. |
| POS-07 | 업데이트는 설정에서 SHA-256 뒤 설치로 넘어간다. 게시자 신뢰를 포지션 문장에 넣지 말 것을 제안한다. | 합의. positioning은 포지션 문장에서 게시자 신원을 주장하지 않는 제한만 가진다. 미서명으로 일관성 점수를 깎지 않는다. |

업데이터가 HTTPS와 해시를 검사하는 사실은 배포 2를 1로 내리지 않은 이유이고, 서명을 대신하지 않는다. 그 판단도 trust 안에 닫혀 있다.

## 5. CL-07 — 로그인 자동 실행

**합의.** 동의 없는 기본 자동 실행은 trust다 (T18, LRN-05).

| 사실 | 근거 | 소유 |
|---|---|---|
| `LaunchAtLogin` 기본값 true | `AppSettings.cs` | trust. 로컬 4에 포함. 다른 축이 기본 켜짐을 다시 감점하지 않는다. |
| 첫 셸이 Run 키를 실행 경로의 `--background`로 맞춘다 | `App.xaml.cs` `ReconcileOnStartup(_settings.General.LaunchAtLogin)` | trust (현재 사용자 Run 키, 권한 모델) |
| 다음 로그온에 창이 없는 이유와 다시 여는 법의 문구가 없다 | LRN-05가 학습성에 남긴 말. LRN-04의 설명 공백과 같다. | learnability. 자동 실행의 동의 여부는 가져가지 않는다. |

매니페스트 `asInvoker`와 세션 로컬 뮤텍스는 T18에서 trust가 확인했다. 두 번째 실행이 첫 인스턴스를 깨우는 조작 감각을 convenience가 따로 말하면, 그 문장은 권한 감점이 아니다.

## 6. CL-10 — 가리기 뒤 `original.png`

**합의.** 잔존 데이터의 주 소유는 trust다 (T07).

`CapturePersistenceService.WriteFinalizeFiles`는 가리기 커밋 때 `original.png`를 다시 그리지 않고 길이만 다시 잰다. 자동 색인은 `rendered.png`가 있으면 그것을 읽는다 (`OcrIndexingService.ResolveImagePath`). 가려진 화면의 이후 색인은 렌더를 보되, 원본 파일의 픽셀은 그 레코드가 지워질 때까지 남는다.

| 조각 | 소유 | 점수 |
|---|---|---|
| 가려지지 않은 `original.png`가 만료까지 남는다 | trust. 로컬 4에 포함 | 추가 감점 없음 |
| 탐지 결과가 인식 문자열 없이 좌표만 넘긴다 (T06) | trust의 강점. POS-11의 “평문 비보존”은 이 조각이다 | 감점이 아님 |
| 가림막을 옮기고 취소하고 레이어로 다시 여는 일 | functionality 강점. POS-11의 설명 후 공유 문장 | 신뢰 감점으로 가져오지 않음. 기능 감점으로도 세지 않음 |
| 탐지 범위의 미탐·오탐을 기능 완성도로 보는 서술 | functionality가 품질을 말할 수 있다 | 신뢰 축의 공백 점수는 trust가 이미 로컬 4에 넣었다. 절차는 어느 축에도 적지 않는다. |

## 7. CL-01 — README F4 / 코드 F9

**병합.** 네 인박스 행을 한 사실의 네 조각으로 합친다.

코드 기본 단축키는 `Hotkey.VkF9`다 (`AppSettings.cs` `UploadGitHubImage`). `SettingsStore.cs`는 수정자 없는 구 F4만 F9로 옮기고, 비어 있으면 F9로 되돌린다. `README.md` 단축키 표는 아직 F4다. 전송은 그 키를 눌렀을 때만 시작하고, 캡처 완료 경로에 묶인 자동 업로드가 아니다 (T11, 네트워크 표면 표).

| 조각 | 인박스 | 주 소유 | 남겨 두는 말 |
|---|---|---|---|
| 표와 기본 키가 달라 사용자가 없는 키를 배운다 | LRN-10 | learnability | 가이드가 F3/F9를 빠뜨리는 학습 공백도 여기. 신뢰 점수를 움직이지 않음 |
| 눌렀을 때 무엇이 어디로 가는지 | T11, T12, T13, T14 | trust | 브라우저 초안, 토큰 경로, DPAPI, 두 번째 URL. 로컬 4에 포함. 키 이름 불일치로는 감점하지 않음 |
| 로컬 설명 문장 밖에 네트워크 목적지가 전역 키로 올라가 있다 | POS-06 | positioning | 목적지를 옵트인으로 내릴 문장만. F4/F9 불일치와 토큰 안전은 가져가지 않음 |
| 기본값이 F9라는 구현 확인 | F-13 | functionality | 코드 기본값 확인만. 워크플로 감점으로 키 이름을 다시 세지 않음 |

## 8. CL-15 — 이미지 168시간

**합의.** 민감정보 수명의 주 소유는 trust다 (T05, C-08).

`CaptureRetention.DefaultImageRetentionHours`는 `7 * 24`이고, `QueueSettings.ImageRetentionHours`의 기본값이 그 상수다. README 저장 위치 절과 같다. 고정 이미지와 동영상은 그 만료에서 빠지고, 개수 300·용량 2GiB는 둘에 적용되며, 고정 항목은 용량 퇴거에서 빠진다. 빠른 저장과 큐 밖 내보내기는 그 만료가 지우지 않는다.

| 축 | 이 사실을 다루는 방식 |
|---|---|
| trust | 화면 정보가 기본 168시간, 그리고 만료 예외(고정·동영상·빠른 저장) 동안 기기에 남는다는 수명. 로컬 4에 포함. |
| convenience (C-08) | 재감점하지 않는다. “일주일 뒤 라이브러리 검색에서 빠진다”는 trust 수명의 결과로만 인용할 수 있다. |
| functionality | 보관 정책을 기능으로 설명할 수 있다. 민감정보 수명으로 기능 점수를 깎지 않는다. |
