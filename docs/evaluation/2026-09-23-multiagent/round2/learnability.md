# 라운드 2 — 학습성

대상: Release 3.0.0 (`117b0ef`). 라운드 1 점수 **2 / 5**를 유지한다. 제품 소스는 수정하지 않았다. 아래 판정은 `CONFLICTS.md`의 조율 제안, 라운드 1 점수 이유, 그리고 그 이유를 다시 연 코드다.

점수 2의 이유(라운드 1 §1·§3): 캡처 버튼과 준비 알림은 있다. 첫 10분에 영역 캡처·녹화·라이브러리·핀·GitHub(코드 기본 F9)를 한 세트로 가르치는 앱 표면은 없다. `IsFirstRun`은 저장만 된다. 앱 안 「사용 방법」은 단축키 이름을 빠뜨린다. 5는 단축키 가족이 첫 화면과 도움에 살아있는 상태, 3은 핵심 흐름을 앱 안에서 따라가고 공백이 설정·심화에 머무는 상태다. 지금은 캡처 한 가지 외에는 문서를 열거나 설정 단축키 탭을 열어야 한다.

## 2. CL-06 — 점수 2 유지

**합의.** 가이드가 좋아도 앱이 침묵하면 2다.

`docs/guides/README.md`는 한국어로 C/X/Z, 편집기 Ctrl+C·Ctrl+S, GIF 20초·200프레임, 언어는 다음 시작·테마는 즉시를 적고 스크린샷 4장이 있다. 그 품질은 사실이다. 학습성 점수는 그 파일을 연 사람을 채점하지 않는다. 앱이 그 파일로 보내는 링크는 `src`에서 검색되지 않았고, 트레이 「사용 방법」(`Shell.HelpText`)은 키 이름 없이 캡처만 말한다. 준비 알림 `ShellRetake_ReadyMessage`는 등록된 캡처 키 한 줄이다. 라운드 1 §3의 문장 그대로다. 문서가 설명해도 앱이 침묵하면 학습성이다.

편의성 4는 그대로 둔다. C-02(창·전체·이전 영역·클릭 통과의 기본 키가 비어 트레이로 가는 반복 마찰)는 편의성의 감점이고 학습성 2와 별개다. 학습성 2는 비어 있는 키를 세지 않는다. 이미 있는 C/X/Z·F3·F9를 첫 10분이 가르치지 않는 침묵을 센다.

| 사실 | 처리 |
|---|---|
| 가이드 본문·스크린샷이 갖춰져 있음 | 인정. 2 → 3의 이유가 되지 않음 |
| README가 F4를 가르침 | 2의 이유 중 하나(CL-01). README만 고쳐도 2는 그대로. 앱 안 도움이 키 세트를 말하지 않음 |
| C-02 빈 기본 키 | convenience 유지. 학습성 점수에 넣지 않음 |
| 한국어/영어 리소스 897=897 | 강점으로 남김. 첫 실행 침묵을 메우지 않음 |

## 3. CL-01 — F4 / F9

**합의.** 표기 불일치의 주 소유는 learnability다.

| 축 | 이 사실에서 소유하는 것 | 학습성 처리 |
|---|---|---|
| learnability | 루트 README 47–48행이 GitHub 첨부를 `F4`로 적고, F3 행이 「F4 이후」라고 적는다. 코드 기본값은 `Hotkey.VkF9`(`AppSettings.cs` `UploadGitHubImage`). 스키마 4 미만의 순정 F4만 F9로 옮긴다(`SettingsStore.cs`). 설정 힌트 `Settings.GitHubIssueUrlHint`와 `GitHub.Failed`는 F9다 | 주 소유. 2에 포함 |
| trust | 그 키가 이미지를 네트워크·브라우저로 보내는 경로 | 재감점 안 함. T11의 행 전체 소유 주장은 **병합**: 표와 기본키의 어긋남만 여기로 가져오고, 전송은 trust에 남긴다 |
| positioning | 단축키가 로컬 설명 문장 밖에 있다는 범위 | 재감점 안 함. README의 F4 글자를 포지션 점수에서 한 번 더 깎지 않는다 |
| functionality | 코드 기본값이 F9이고 사용자 조합의 F4는 남는다는 확인(F-13) | 재감점 안 함 |

가이드 `docs/guides/README.md`는 F3/F4/F9를 다루지 않는다. 그래서 저장소 문서를 연 사람은 없는 기본 키를 배우거나, 핀 키를 문서에서 못 만난다. 앱 안 설정 문구는 F9로 맞다. 불일치는 앱 카피가 아니라 README다.

## 4. CL-13 — GIF 20초

**합의.** 상한을 제품이 숨기면 그 침묵의 주 소유는 learnability다. 상한 자체를 ScreenToGif 대비 기능 감점으로 받지 않는다는 조율에도 동의한다.

현재 3.0.0은 그 조건에 해당하지 않는다. GIF를 고른 내보내기 창은 한도를 문장으로 그린다.

- `VideoExportDialog` 생성자가 GIF 패널에 `MediaExport_GifLimits`를 붙인다. 한국어 값은 「GIF는 최대 20초, 200프레임입니다. 긴 변과 프레임 속도를 선택하세요. 소리는 포함되지 않습니다.」
- 구간이 상한을 넘으면 상태 줄이 `MediaExport_TrimGif`(「선택 구간을 20초 이하로 줄이세요」)다.
- `docs/guides/README.md` 33행도 같은 20초·200프레임을 적는다.
- 녹화 자체는 20초로 잘리지 않는다. 상한은 GIF 내보내기의 규율이다. 녹화 시작 창이 미리 말하지 않는 것을 숨김으로 치지 않는다.

따라서 학습성 2에 GIF 상한을 넣지 않는다. 기능 점수에서 이 상한을 감점하는 주장도 학습성으로 가져오지 않는다.

자동 자르기는 별개의 짧은 공백이다. `VideoEditorWindow.OpenExport`는 `ExportGif`에서 `TryAutoTrimForGif`로 끝점을 20초로 옮긴다. 대화상자 요약 줄은 생성자에서 복제 문서의 트림 전 길이로 찍히고(`VideoExportDialog` 49행 `Clone`, 67–68행), `Changed`는 그 요약 문장을 다시 쓰지 않는다. 전용 「20초로 당겼습니다」 문장은 없다. 한도 문장 `MediaExport_GifLimits`는 그 자리에 있으므로, 이것을 「상한을 숨김」으로 올리지 않는다. 학습성 보조 메모로만 두고 점수는 바꾸지 않는다. Windows에서 그 요약 줄이 실제로 20초보다 길게 보이는지는 GUI로 확인하지 않았다.

## 5. CL-07 — 로그인 자동 실행

**합의.** `LaunchAtLogin` 기본값 true와 Run 키에 `--background`를 맞추는 동의 없는 자동 실행은 trust가 소유한다. 학습성은 그 불리언을 다시 깎지 않는다.

학습성에 남는 것은 설명 공백 하나다. 설정 체크박스 본문은 「로그인 시 자동 시작」(`Text_98F1681CB686`), 도움은 「Windows에 로그인하면 MyCapture를 자동으로 실행합니다」(`Text_F3C7FE27A258`), 아래 설명은 「현재 사용자 계정에만 적용됩니다. 관리자 권한이 필요하지 않습니다」(`Text_963745AB00F4`)다. 다음 로그온에 라이브러리 창이 없고 트레이만 남는다는 문장은 없다. `StartupRegistrationService.BackgroundSwitch`는 `"--background"`이고, 그 스위치가 있으면 시작이 창을 열지 않는다. 이 공백은 라운드 1 LRN-04로 점수 2 안에 이미 한 번 들어 있다. trust 감점과 같은 사실을 두 번 세지 않는다.

## 6. CL-16 — M/X 거짓 이름

**합의.** 학습성은 보조 축이다. 같은 사실을 점수 2에 다시 넣지 않는다. 형광펜이 없는 CL-02와 한 주장으로 합치지 않는다.

| 조각 | 주 소유 | 근거 |
|---|---|---|
| 자동화 이름 `{0} 도구 ({1})`(`Text_1BA9F7001237`)에 모자이크 `M`, 자르기 `X`가 들어감 | accessibility | `AddToolButton` 호출. `HandleShortcut`의 switch는 `V R A P T I Q W`와 수정자 조합뿐이고 `Key.M`·`Key.X`가 없다 |
| 모자이크 툴팁 「가릴 영역을 드래그하세요 (M)」(`Text_3F8046019B33`) | accessibility의 같은 사실. 학습성은 보조 | 이름과 같은 거짓 글자. 문구 품질만 여기 메모 |
| 자르기 힌트 「Enter로 확정」(`Tools_CropHint`)인데 마우스 업이 `ApplyCrop` | 거짓 확정 문장은 CL-16의 보조 문구. 즉시 적용이라는 동작 마찰은 convenience | `OnSurfaceMouseUp`. `HandleShortcut`에 자르기 확정용 Enter가 없다 |
| 형광펜 도구 없음, `HighlighterAlpha`만 설정에 있음 | functionality (CL-02) | 학습성 재감점 안 함 |

편의성 C-06은 이름 불일치와 마우스 업 즉시 자르기를 한 줄에 두었다. **병합:** 이름·힌트가 키와 어긋나는 부분은 CL-16(주 소유 accessibility)으로 보낸다. 자르기가 마우스 업에 바로 적용되는 워크플로 마찰은 convenience에 남긴다. 학습성은 둘 중 어느 것도 다시 채점하지 않는다.

## 7. 편의성 라운드 1에서 넘어온 나머지 겹침

편의성 점수는 4다. 채점 이유는 영역 캡처가 키 한 번과 드래그로 이어지고, 빈 기본 키·녹화의 추가 시작 확인·완료와 클립보드가 묶인 마찰이 남아서다. 그 점수를 학습성이 다시 깎지 않는다.

| 주장 | 판정 | 주 소유 | 학습성이 하는 일 |
|---|---|---|---|
| C-01 복사 실패를 「저장이 완료되지 않았습니다」로 보여 편집기를 붙잡음 | **합의** | convenience | 문구가 저장과 복사를 구분하지 못하는 점은 보조 메모. 편집기가 남는 동작은 재감점 안 함 |
| C-02 창·전체·이전 영역·클릭 통과 기본 키 없음 | **합의** | convenience | CL-06과 같이 학습성 2와 별개 |
| C-03 단축키 칸이 문자열이고, 충돌 시 이전 조합으로 되돌림 | **합의** | convenience | 재지정 속도는 재감점 안 함 |
| C-05 편집기 Ctrl+C가 선택 주석이 아니라 전체 확정·닫기 | **합의** | convenience | 키의 뜻은 보조 메모. 동작 마찰은 재감점 안 함 |
| C-06 M/X와 즉시 자르기 | **병합** | 이름은 accessibility(CL-16), 즉시 자르기는 convenience | §6 |
| C-14 언어를 바꿔도 다음 실행 전까지 창 문구가 그대로 | **합의** | learnability | 이미 LRN-13으로 2 안에 있음. 편의성 4에 다시 넣지 않음 |

## 9. 미확인

- Windows에서 5초 준비 알림이 보이는지, 닫은 뒤 사용자가 종료로 믿는지. 라운드 1과 같다.
- GIF 자동 자르기 뒤 요약 줄이 20초보다 긴 숫자로 남는지. 생성자 순서로는 그렇게 읽히고, 창 재현은 하지 않았다.
- `docs/guides/shots` 4장이 3.0.0 창과 같은지. 가이드 품질을 점수로 쓰지 않으므로 2의 유지와는 무관하다.
