2026-10-10. Microsoft Store에 게시된 4.1.0 목록(Store ID `9PB33MC095VR`)을 점검하고, 코드와 문서에서 읽은 제품 철학으로 마크·색·문구·Store 자산을 다시 정했습니다. 결과 기준은 [`design-system/mycapture/MASTER.md`](../../design-system/mycapture/MASTER.md)입니다.

## 읽어 낸 철학

코드와 문서가 일관되게 지키는 약속은 다섯 가지입니다.

1. **화면이 주인공**: 크롬은 조용한 그래파이트, 색은 의도의 순간에만 (MASTER의 기존 원칙).
2. **놓는 순간 남는다**: 놓으면 라이브러리 저장과 클립보드 복사가 먼저, Esc로 닫아도 원본 유지 (README 단축키 표).
3. **내가 보내기 전까지 PC 밖으로 나가지 않는다**: 계정·광고·자동 업로드·텔레메트리 없음, 로컬 OCR, 빠른 가리기는 평문을 남기지 않음.
4. **언제든 되돌린다**: 이미지·영상 모두 원본 위의 레이어.
5. **손이 기억한다**: `Ctrl+Shift+C / X / Z`, `F3`.

브랜드 문장은 이 다섯을 한 줄로 줄인 것입니다: **보이는 그대로, 내 PC에 남깁니다.**

## 색을 마젠타로 바꾼 이유

- 캡처하는 화면의 색이 아님: Teams 보라(`#6264A7`, 238°)와 89°, Windows 기본 파랑(`#0078D4`, 206°)과 121° 떨어져 있음.
- 주석 색이 아님: 편집기 견본(빨강·노랑·초록·파랑·검정·흰색)에 없음.
- 어떤 화면에서도 보임: 상대 휘도 0.235로 흰 문서 3.68:1, 어두운 편집기 4.5:1.
- 위험 색과 구분: 위험 색을 따뜻한 빨강(`#FF6B5F`, 밝은 테마 `#C62828`)으로 옮겨 30° 이상 떨어뜨림.

6개 테마의 모든 강조 쌍은 기존 테스트가 요구하는 대비를 만족합니다(잉크 대 마젠타 5.34:1, 가장 낮은 포커스 링 4.98:1). 영상 타임라인의 레이어 색(텍스트 보라, 프레임 청록)은 브랜드가 아닌 식별 색이라 그대로 둡니다.

## 확인 범위와 남은 일

- Linux에서 `EnableWindowsTargeting`으로 전체 솔루션을 Release 빌드했습니다(경고·오류 0). WPF 앱 테스트는 Windows CI에서 확인해야 합니다. Core의 테마 대비 테스트는 Linux에서 통과했습니다.
- `generate-icons.ps1`은 PowerShell 파서로 문법을 확인했습니다. System.Drawing은 Windows 전용이라 커밋한 `.ico`는 같은 기하를 그리는 별도 렌더러로 만들었습니다. Windows에서 스크립트를 다시 실행하면 같은 모양으로 다시 생성됩니다.
- 가이드 스크린샷(`docs/guides/shots/`)과 게시된 Store 스크린샷은 아직 아이리스 색입니다. Windows에서 `--selftest-ux-review`와 `--selftest-store-shots`로 다시 만들어야 합니다.
