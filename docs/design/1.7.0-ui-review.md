# MyCapture 1.7.0 UI 검토

2026-09-08. 합성 데이터로 실제 WPF 창의 초기·수정 후·최종 승인 렌더를 검토했습니다. **발견한 시각 결함의 수정, 네이티브 포인터의 모니터 경계 통과·복귀 및 제목 표시줄 검토를 완료했습니다.** 포인터 앵커 수정 후 집중 테스트 57개와 리드의 최종 전체 재실행 750개를 통과했습니다. 소스 검토, 오프스크린 렌더와 네이티브 조작 검증을 구분합니다.

## 확인한 근거와 수정

- 사용자 첨부 이미지의 빨간 상자는 밝은 OS 제목 표시줄과 기본 밝은 세로 스크롤바를 가리킵니다. 첨부 이미지는 warm/yellow 팔레트이며, 현재 [디자인 기준](../../design-system/mycapture/MASTER.md)은 Focus Portal graphite/cyan입니다.
- `GalleryWindow`는 현재 `Window.Standard`를 명시적으로 사용합니다. `ModernWindowChrome`은 네이티브 어두운 캡션과 현재 팔레트의 캡션·텍스트·테두리를 적용하며 고대비에서는 OS 색상을 존중합니다. 기존 설정을 유지했습니다.
- 공통 컨트롤 리소스에 ScrollBar 스타일이 없어 기본 스크롤바가 섞였습니다. 세로·가로 track과 네이티브 page 명령을 유지하는 graphite 스크롤바를 추가했습니다. hover, dragging 및 고대비 상태를 정의했습니다.
- 라이브러리 카드의 직접 핀 버튼을 휴지통으로 바꾸고 더보기 안에 핀 고정을 추가했습니다. 복사·삭제·더보기의 접근성 이름과 툴팁이 동작에 맞습니다. 삭제 확인과 기존 키보드 조작은 유지합니다.
- 저장소 설정에 관리 이미지의 7일 보관과 예외를 설명했습니다. 기존 자동 높이 및 설명 텍스트 스타일을 사용합니다.
- 색인 안내를 자동 색인 동작에 맞게 바꿨습니다. 수동 버튼은 미색인 항목의 재시도를 위한 보조 동작으로 유지합니다.

## 실제 렌더 근거와 발견한 문제

초기 및 중간 산출물은 저장소의 `artifacts/validation/ux-review-v1.7.0`과 `artifacts/validation/ux-review-v1.7.0-final`, 최종 승인 산출물은 `artifacts/validation/ux-review-v1.7.0-accepted`에 있습니다. 스케치가 아니라 합성 이미지·텍스트를 넣은 실제 WPF 창 5종(Gallery, Settings, 이미지 편집기, Pin, 동영상 편집기)을 생성했습니다. 기본/축소 크기를 96/144/192 DPI의 오프스크린 출력 밀도로 렌더했으며, Settings는 9개 탭을 검토했습니다. 최종 창 비유지 UX 진단은 종료 코드 0으로 완료됐습니다.

이 호스트의 실제 모니터는 3440×1440 및 1366×768이고 둘 다 96 DPI입니다. 144/192 DPI 산출물은 렌더 출력 밀도 검증이며 Windows의 실제 서로 다른 모니터 배율에서 조작한 결과가 아닙니다.

| 실제 렌더에서 발견한 문제 | 반영한 수정 / 현재 상태 |
|---|---|
| 이미지 편집기의 선 종류 ComboBox가 밝은 기본 Windows 색상으로 표시 | 공통 graphite/cyan ComboBox·드롭다운·항목·포커스 템플릿 추가. 고대비는 시스템 색상 사용 |
| 축소 Settings에서 사이드바의 아래쪽 분류가 잘려 포인터로 접근 불가 | 분류 목록을 세로 스크롤 영역으로 변경 |
| 축소 이미지 편집기에서 속성 패널이 가려짐 | 속성 패널을 접근할 수 있도록 축소 레이아웃 수정 |
| 축소 동영상 편집기에서 영상 미리보기 영역이 무너짐 | 축소 레이아웃의 미리보기 공간 확보 |
| 중간 렌더에서 색상 견본 오른쪽 끝 일부가 잘림 | 수정 후 승인 렌더에서 축소 편집기의 견본 6개 모두 표시됨을 리드가 확인 |
| 중간 동영상 렌더에서 도움말의 마지막 짧은 문구가 홀로 줄바꿈 | 수정 후 승인 렌더에서 마지막 문구가 홀로 줄바꿈되지 않음을 리드가 확인 |

## 검증 상태

| 화면 | 확인할 결과 | 상태 |
|---|---|---|
| Gallery 최소 크기 및 기본 크기 | 카드 명령 순서, 제목/요약 간격, 검색 placeholder, 안내 줄바꿈, 스크롤바 | 실제 렌더 검토 완료; 관련 전체 회귀 PASS |
| Settings 9개 탭 | 분류 접근, 설명 줄바꿈, 입력 레이블/버튼 정렬 | 실제 렌더 검토 및 분류 스크롤 수정 반영 |
| 이미지 편집기 | 도형 선/채우기 컨트롤, 속성 패널, 색상 견본 | 실제 승인 렌더 확인; 견본 6개 표시, 속성 패널 접근 |
| 녹화 및 동영상 편집기 | 영역 안내, 변환 상태, GIF 프리셋, 텍스트 시간 핸들 | 승인 렌더에서 미리보기·전송 제어·상태가 보이고 도움말 줄바꿈 수정 확인. 녹화 동작 검증은 별도 |
| Pin | 코드/표 미리보기, 원문 복사, 화면 경계 이동 | 실제 렌더, 네이티브 끝 좌표, 포인터 경계 통과·복귀 PASS; 실제 Ctrl+C 이미지 이벤트 PASS. Ctrl+더블클릭은 회귀로 확인 |
| DPI 및 키보드 | 출력 밀도, Tab 포커스, 긴 한국어 문구, reduced motion | 96/144/192 렌더 수행. 실제 모니터는 모두 96 DPI; 나머지 조작별 결과는 별도 기록 필요 |
| 네이티브 캡션 | 실제 DWM 색상과 창 조작 | PASS — 어두운 캡션, 제목·버튼 정렬, 캡션 드래그; 콘텐츠 렌더와 별도 검토 |

네이티브 Pin 창은 두 모니터 끝에서 `[0,0]`, `[3200,1308]`, `[3440,0]`, `[4566,636]`의 네 목표 좌표 모두에 도달했습니다. 실제 포인터 드래그에서도 `[3200,100] → [3390,100] → [3580,100] → [3390,100] → [3200,100]`으로 두 번째 모니터에 완전히 진입한 뒤 복귀했고 리드가 독립 확인했습니다. `artifacts/validation/ux-review-v1.7.0-pointer-fixed`의 `native-pointer-validation.md`, 입력 추적과 두 모니터 위치 PNG가 근거입니다. 지연 입력에서 전역 커서 위치로 앵커를 계산하던 문제는 MouseDown 이벤트 좌표를 사용하도록 수정했습니다.

실제 Ctrl+C는 `artifacts/validation/ux-review-v1.7.0-pointer/pin-input-events.txt`의 16:00:24 UTC `IMAGE identity=True; modifiers=Control`로 확인했습니다. fixture는 사용자 클립보드 쓰기를 대체하므로 이미지 이벤트 검증으로 범위를 한정합니다. modifier 유지 제약으로 네이티브 Ctrl+더블클릭은 실행하지 않았고 회귀로 확인했습니다. 대화형 fixture는 검증 후 종료했으며 정상 종료 코드 0 주장은 별도 비유지 렌더 실행에만 적용합니다.

실제 Gallery 캡션 근거는 `artifacts/validation/ux-review-v1.7.0-native/gallery-native-caption.png`입니다. 리드가 어두운 네이티브 제목 표시줄, 제목·버튼 정렬 및 캡션 드래그를 확인했습니다.

사용자 데이터를 삭제하거나 변경하지 않고 합성 데이터로 검토했습니다. 진단 임시 폴더 자동 생성 수정 후 리드의 최종 전체 Release 실행은 종료 코드 0, 경고 0, 오류 0으로 완료됐고 Core 358개 + App 392개 = 750개 테스트를 통과했습니다. 근거는 `build/logs/build.log`와 `build/logs/test.log`입니다. 패키지·PR CI·게시 상태는 [소스 동결 시점 검증 기록](../releases/1.7.0-validation.md) 및 이후 GitHub 릴리스 본문·로컬 릴리스 증거를 따릅니다.

설치본 라이브러리의 UIA 트리는 확인했지만 스크린샷에는 대상 창 대신 배경이 나타났습니다. 원인은 확인되지 않았으며, 라이브러리에 화면 캡처 제외 설정이 적용됐다는 근거로 취급하지 않습니다.

최종 진단 보안 수정에서 `--selftest-ux-review`는 출력 경로 인자 없이 실행합니다. BCL `Directory.CreateTempSubdirectory("MyCapture-ux-review-")`가 새 폴더를 생성하고 `UX_REVIEW_OUTPUT=...`와 진단 추적으로 위치를 알립니다. 이전의 11개 경로 허용 목록 테스트는 생성·격리·정리 테스트 2개로 교체됐습니다. 최종 전체 750개 테스트(Core 358, App 392)를 통과했고, 인자 없는 smoke도 임시 `MyCapture-ux-review-5amufqeb.loc` 폴더에서 종료 코드 0·보고서 PASS입니다. 레이아웃은 변경되지 않았으며 기존 승인 렌더 검토를 유지합니다. 두 번째 후보의 신규 high CodeQL 경고 17개 이후 최종 새 head의 보안 분석 결과는 별도 대기입니다.
