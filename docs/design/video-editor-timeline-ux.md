# 녹화 편집 타임라인 UI/UX 시나리오 — 2단(개요 + 세부) 구조

목적: 사용자 스케치 반영. **위 라인 = 전체 라인(개요, 세세하지 않음)**, **아래 라인 = 위에서 선택한 구간을 확대한 세세한 라인**. 프레임 단위 정밀 편집과 전체 조망을 동시에 제공한다.

관련 코드: `src/MyCapture.App/Recording/VideoEditorWindow.cs` (현재는 단일 스크러버 + 트림 핸들 2개)

---

## 1. 개념 (Overview + Detail / Brush-and-Zoom)

프로 NLE의 소스 모니터·오디오 편집기가 쓰는 표준 패턴이다.

```
┌──────────────────────────── 위: 전체 라인 (OVERVIEW) ────────────────────────────┐
│  |■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■|      │
│           └─ 뷰포트(brush): 아래 라인이 보여주는 구간 ─┘                          │
│  ▲ playhead                          [In]════════[Out] 트림 선택                  │
└───────────────────────────────────────────────────────────────────────────────┘
        ╲                                     ╱   (위 뷰포트 → 아래 전체로 확대)
         ╲___________________________________╱
┌──────────────────────────── 아래: 세부 라인 (DETAIL / ZOOM) ─────────────────────┐
│  | · · · · · · · · · · · · · · · · · · · · · · · · · · · · · · · · · · · · · · |  │
│    프레임 눈금(fps 기준) ─ 한 칸 = 1프레임                                        │
│  ▲ playhead (프레임 정밀)              [In]══[Out]                                │
└───────────────────────────────────────────────────────────────────────────────┘
```

- **위(개요)**: 클립 전체(0 ~ duration)를 한눈에. 눈금은 성기게(초 단위 major tick). 여기서 트림 In/Out 핸들과 재생헤드를 크게 잡고 움직인다. "뷰포트(brush)" 사각형이 아래 라인이 현재 보여주는 구간을 나타낸다.
- **아래(세부)**: 위의 뷰포트 구간만 가로 전체로 확대. 눈금은 **프레임 단위**(1칸 = 1프레임 = 1000/fps ms). 여기서 프레임 정밀 재생헤드 이동·트림 미세조정을 한다.

## 2. 상호작용 매핑 (기존 키 재설계와 일관)

| 동작 | 위(개요) | 아래(세부) |
|---|---|---|
| 클릭/드래그 | 재생헤드를 그 위치로(큰 이동) | 재생헤드를 프레임에 스냅해 이동(세밀) |
| 뷰포트(brush) 좌우 드래그 | 아래가 보여줄 구간 이동 | — |
| 뷰포트 가장자리 드래그 | 확대율(zoom) 변경 | — |
| In/Out 핸들 | 큰 단위로 자르기 | 프레임 단위로 미세 조정 |
| 방향키(전역) | ←/→ 크게 이동(개요 기준) | Ctrl/Shift+←/→ 1프레임(세부 기준) |
| 마우스 휠(아래 위에서) | — | 확대/축소(재생헤드 중심) |

키 규칙은 이미 반영된 "←/→ 크게, Ctrl·Shift+←/→ 1프레임"과 정확히 대응된다: **위 라인 = 크게, 아래 라인 = 프레임**.

## 3. 화면 구성 (VideoEditorWindow 레이아웃 갱신안)

```
Row 0: 프리뷰(+로딩 오버레이)
Row 1: 위 타임라인(개요)   ← 전체 라인 + 뷰포트 brush + 트림 핸들(큰 단위)
Row 2: 아래 타임라인(세부) ← 뷰포트 구간 확대 + 프레임 눈금 + 트림 핸들(프레임)
Row 3: 컨트롤 버튼 2행 (스크롤 없음, 고정 크기, 겹침 없음)
Row 4: 상태줄 + 위치 라벨(mm:ss.fff / mm:ss.fff · 프레임 N)
```

- 두 타임라인은 재생헤드를 **공유**한다(한쪽을 움직이면 다른 쪽도 갱신). 위의 뷰포트는 아래의 가시 범위와 항상 동기화.
- 기본 상태: 위 = 전체 클립, 아래 = **상단 굵은 coarse 눈금 한 구간**. 상단에는 선택 밖 음영·굵은 테두리·큰 양끝 grip을 표시하고, 연결선으로 선택 구간이 아래 전체 폭에 확대됨을 보여준다. `전체 보기`를 누르면 아래도 전체 범위로 되돌아간다.
- 상단 굵은 눈금은 하단에도 같은 두께로 반복하고, 그 사이에 얇은 프레임 눈금을 배치해 "굵은 인덱스 사이의 프레임을 편집한다"는 계층을 명확히 한다.
- 하단 캡션은 `시작 mm:ss.fff → 끝 mm:ss.fff | 범위 ... · N프레임`을 실시간 표시한다.

## 4. 상태·피드백 (기존 규칙 계승)

- 로딩 중에는 두 타임라인 모두 **비활성(회색)**, 프리뷰에 "불러오는 중… N%".
- 준비 완료 후 활성화. 트림 선택 시 두 라인 모두 In~Out 구간을 강조색(Accent)으로 표시.
- 위치 라벨: `00:03.400 / 00:12.000 · 프레임 51/180`.
- 프레임 스냅: 아래 라인의 모든 이동은 프레임 경계에 스냅(FrameStepCalculator.SnapToFrame 재사용).

## 5. 순수 로직 재사용/신규 (테스트 가능하게)

- 신규 `TimelineViewport`(Core, 순수): `{ClipDurationMs, ViewStartMs, ViewEndMs}` + `PxToMs(px,width)`, `MsToPx(ms,width)`, `Zoom(centerMs, factor)`, `Pan(deltaMs)`, 불변식(0<=start<end<=duration, 최소 폭 = 프레임 여러 개). → 단위 테스트로 확대/이동/클램프 검증.
- 기존 `FrameStepCalculator`(스냅·프레임 인덱스)와 `TrimSelection`(In/Out) 그대로 재사용.
- WPF 레이어(`VideoEditorWindow`)는 두 개의 커스텀 눈금/핸들 그리기 컨트롤을 얹고, 위 로직에 위임.

## 6. 단계적 구현 계획

1. `TimelineViewport` (Core) + 단위 테스트.
2. 아래 라인에 프레임 눈금 렌더 + 재생헤드 스냅.
3. 위 라인에 뷰포트 brush(드래그 이동/가장자리 확대) + 아래와 동기화.
4. 트림 핸들을 두 라인에 연결(위=큰 단위, 아래=프레임).
5. 휠 확대/축소, 위치 라벨에 프레임 번호 추가.
6. 실기 self-test/STA 테스트로 로딩·비활성·정밀 이동 검증.

## 7. 접근성

- 두 타임라인 슬라이더에 AutomationProperties 이름("전체 타임라인", "세부(프레임) 타임라인").
- 모든 마우스 동작에 키보드 대안(방향키·Home/End·I/O) 유지.
- 색만으로 트림 구간을 표시하지 않고 핸들 위치·라벨 병기.

> 이 문서는 사용자 스케치를 코드 구조로 옮긴 설계안이다. 실제 구현은 위 6단계로 진행하며, 각 단계는 빌드+테스트+(가능 시)실기 self-test로 검증한다.

## 8. 벤치마크 조사 결과 (실제 편집기 관행)

출처(웹 확인):
- **Adobe Premiere** — 타임라인 하단의 "zoom scroll bar": **막대의 가장자리를 드래그하면 확대/축소, 막대 몸통을 드래그하면 이동(pan)**. 재생헤드는 파란 삼각형 마커 + 세로선이며 드래그로 현재 시각 변경. → 우리 "뷰포트 brush" 모델과 정확히 일치.
- **Camtasia** — **zoom 슬라이더** + **"전체 프로젝트를 타임라인에 맞춤(fit)"** 버튼. 프레임 이동은 `,`/`.`(쉼표/마침표) 키, 확대/축소 `Ctrl+Shift+=` / `Ctrl+Shift+-`.
- **ScreenToGif / Camtasia** — 프레임 스텝에 `,` `.` 키 사용.

### 확정 관행 반영
1. 상단 개요 막대의 **뷰포트 brush**: 몸통 드래그=이동, **양 끝(엣지) 드래그=확대/축소**(Premiere식).
2. **"전체 보기(Fit)" 버튼** 추가(Camtasia식 zoom-to-fit) — 아래 세부 라인을 전체로 되돌림.
3. 프레임 이동 키 별칭: 기존 `Ctrl/Shift+←/→`에 더해 **`,`(이전 프레임) / `.`(다음 프레임)** 추가.
4. 재생헤드는 **양 라인 공유**, 아래 라인에서 프레임 경계 스냅.
5. 아래 라인 위에서 **마우스 휠 = 재생헤드 중심 확대/축소**.
6. 위치 라벨에 **프레임 번호** 병기: `00:03.400 / 00:12.000 · 프레임 51/180`.

### 핵심 순수 타입 (테스트 가능)
`TimelineViewport { ClipDurationMs, ViewStartMs, ViewEndMs }`
- `MsToPx(ms, widthPx)`, `PxToMs(px, widthPx)` — 아래 세부 라인 좌표 변환
- `Zoom(centerMs, factor)` — 중심 고정 확대/축소, 최소 스팬(프레임 몇 개) 클램프
- `Pan(deltaMs)` — 이동, [0, duration] 클램프
- `FitAll()` — 전체 보기
- 불변식: `0 <= ViewStart < ViewEnd <= Duration`, `ViewEnd-ViewStart >= 최소 스팬`
