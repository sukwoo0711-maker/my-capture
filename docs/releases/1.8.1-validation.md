# 1.8.1 patch release validation

This document defines the patch gates; it is not a passing release record. Apply the source provenance, seven packaged diagnostics, installer, and isolated diagnostic-restart requirements in the [1.8.0 runbook](1.8.0-validation.md), using version `1.8.1`, Windows binary version `1.8.1.0`, and `artifacts/release/1.8.1` throughout. Preserve the historical 1.8.0 evidence.

## Patch scope and measurements

The confirmed starting path acquires the full virtual desktop synchronously before the region selector opens. Native readback, a large managed staging buffer, and its bitmap copy contribute work before the user sees the selector. The accepted coordinator change moves acquisition off the UI thread, reserves a single session immediately, and discards late results after cancellation or shutdown. The accepted direct-readback implementation writes `GetDIBits` output into a locked `WriteableBitmap` back buffer, checks stride and complete row count, then unlocks and freezes the completed image. It eliminates the full-frame managed staging array and additional bitmap copy.

## Recorded local evidence

The acquisition comparison used the same 4806×2466 virtual desktop in sequential quiet windows, with one cold-process sample and five warm samples per implementation. It ran a dedicated STA acquisition process, without overlays, global hotkeys, saved images, or forced GC. The baseline engine matches `a7460e0`; the after report records source `5b6dcd09765142f261a5fbc9fb748582a54a0d06` and its engine hash. This is implementation-level evidence, not a claim that either measurement source is the final release commit.

| Acquisition metric | Before | After |
| --- | ---: | ---: |
| Warm elapsed-time median, five samples | 110.791ms | 81.285ms |
| Warm calling-thread managed allocation median | 47,408,472 bytes | 1,880 bytes |
| Cold-process elapsed time, one sample | 323.274ms | 219.817ms |
| Warm acquisition-thread CPU median | 31.250ms | 46.875ms |

Cold samples exclude the resident application's prewarm and must not be presented as its normal first-hotkey latency. Allocation counts exclude unmanaged image surfaces. Each sample in both reports recorded +1 Gen0, +1 Gen1, and +1 Gen2 collection: there is no demonstrated reduction in GC counts. Acquisition-thread CPU did not improve in these samples. The trials were sequential rather than repeated/interleaved, so the elapsed-time and allocation results do not establish lower overall CPU use or elimination of system-wide stutter. Retained source evidence: `artifacts/validation/hotkey-latency/acquisition-before.json`, `acquisition-after.json`, and `acquisition-comparison.json`.

A separate dispatcher diagnostic performed three actual-capture samples per implementation with a requested 16ms timer interval. Each synchronous sample delivered zero ticks during acquisition; each asynchronous sample delivered four. Maximum tick gaps were 99.111–103.194ms before and 31.556–35.814ms after. These observations demonstrate dispatcher progress during acquisition, not a guaranteed 16ms response budget. The reported latest GC pause metric was below 1ms; it is not the sum of all pauses during the run and must not be used as such.

The persistent-application control at integrated source `84352391dda53eadb3833077981f62d05f4b4e79` ran the actual coordinator on one STA `Application`/dispatcher with production PerMonitorV2 awareness and a 96-DPI synthetic fixture. All three real MTA acquisitions returned the expected fixture color, all overlays reached their actual `ContentRendered` event on the owner thread, and each cancel was followed by a verified repaint to a different known color. The diagnostic exited zero with `RESULT: PASS` and `DispatcherShutdownFinished=True`.

It is not a baseline comparison, global-hotkey test, recording-exclusion test, or mixed-DPI hardware claim. Only fixture color bytes, geometry, thread/DPI state, and timing were logged; no images were saved. Retained output: `artifacts/validation/persistent-capture/actual-coordinator.stdout.log` and its empty stderr companion.

These local results do not complete the remaining final-head full tests, security checks, clean-main package validation, or publication gates. Keep their exact source commits and artifacts separate from the final release evidence. UI responsiveness, acquisition duration, total hotkey-to-render time, and system-wide stutter remain distinct outcomes.

## Required patch checks

- Verify dispatcher responsiveness during blocked acquisition, single-flight behavior across rapid hotkeys and advanced capture, cancellation until the native call drains, exactly one session-close notification, failure/retry, and no late overlay after disposal or dispatcher shutdown.
- Verify a fresh frozen image per accepted request, current recording-exclusion checks before showing any capture window, and preservation of advanced-capture/editor behavior. Exercise repeated captures and recording concurrently where supported.
- Validate the integrated direct-readback path with real pixels, cursor behavior, negative desktop origins, and the supported display/DPI arrangements. Report any hardware coverage that remains unavailable.
- Run all required full Release tests and security checks on the exact candidate. Package only verified clean `origin/main` after review/integration; keep the release tag, manifest `SourceCommit`, and artifact hashes aligned with that source.
