# 1.8.1 patch release validation

This document defines the patch gates; it is not a passing release record. Apply the source provenance, seven packaged diagnostics, installer, and isolated diagnostic-restart requirements in the [1.8.0 runbook](1.8.0-validation.md), using version `1.8.1`, Windows binary version `1.8.1.0`, and `artifacts/release/1.8.1` throughout. Preserve the historical 1.8.0 evidence.

## Patch scope and measurements

The confirmed starting path acquires the full virtual desktop synchronously before the region selector opens. Native readback, a large managed staging buffer, and its bitmap copy contribute work before the user sees the selector. The coordinator change moves acquisition off the UI thread, reserves a single session immediately, and discards late results after cancellation or shutdown. Direct-readback allocation work is being validated separately before integration.

On the final integrated candidate, record cold and warm capture measurements under an agreed quiet workload. Keep desktop dimensions, display/DPI arrangement, source commit, acquisition time, UI dispatcher response, first-render time, managed allocation, and GC counts with the results. Compare the same acquisition and timing boundaries. UI responsiveness, acquisition duration, total hotkey-to-render time, and system-wide stutter are different outcomes; do not substitute one for another. No final performance numbers or release-pass status are asserted here.

## Required patch checks

- Verify dispatcher responsiveness during blocked acquisition, single-flight behavior across rapid hotkeys and advanced capture, cancellation until the native call drains, exactly one session-close notification, failure/retry, and no late overlay after disposal or dispatcher shutdown.
- Verify a fresh frozen image per accepted request, current recording-exclusion checks before showing any capture window, and preservation of advanced-capture/editor behavior. Exercise repeated captures and recording concurrently where supported.
- Validate the integrated direct-readback path with real pixels, cursor behavior, negative desktop origins, and the supported display/DPI arrangements. Report any hardware coverage that remains unavailable.
- Run all required full Release tests and security checks on the exact candidate. Package only verified clean `origin/main` after review/integration; keep the release tag, manifest `SourceCommit`, and artifact hashes aligned with that source.
