# MyCapture 1.7.0 검증 기록

기준일: 2026-09-08 (Asia/Seoul). **이 문서는 소스 동결 시점의 검증 기록입니다. 로컬 전체 테스트, WPF 렌더와 네이티브 조작 근거를 아래에 구분하며, 이후 PR CI·통합·패키지·게시 결과는 GitHub v1.7.0 릴리스 본문과 `artifacts/validation`의 릴리스 증거에 기록합니다.**

대상: Windows 11 21H2(build 22000) 이상, x64. 배포 계약: self-contained, offline, unsigned, MIT.

## 기준과 현재 상태

[13개 개선 목표와 담당 경계](../ux-improvements-v1.7.0-plan.md)를 기준으로 합니다. 기준 버전은 `origin/main`의 `a7a3a1540958512131a4077551eff45963cec99a`입니다. 최종 후보 SHA와 통합 SHA는 아직 확정하지 않았습니다.

수정 전 기준 빌드는 Windows 11 build 26200, x64, .NET SDK 10.0.400에서 Release 빌드 및 701개 테스트(342 Core, 359 App)를 통과했습니다. 이는 **최종 1.7.0 검증 결과가 아닙니다**. 최초 sandbox restore는 NuGet 취약점 피드 접근 오류 NU1900으로 실패했고, 감사 기능을 끄지 않은 허가된 네트워크 재실행으로 기준 빌드를 완료했습니다.

실제 설치본의 라이브러리를 대상으로 한 최초 스크린샷에는 대상 창 대신 배경이 표시됐습니다. UIA 트리에서는 해당 창을 확인했으나, 실패 원인은 확인하지 못했으며 라이브러리 캡처 제외 설정의 근거로 취급하지 않습니다. 이후 합성 데이터로 실제 WPF 창을 생성한 렌더 검증을 완료했습니다. 사용자 캡처를 보관 만료 테스트에 사용하지 않았습니다.

최종 렌더는 `artifacts/validation/ux-review-v1.7.0-accepted`에 있으며, 창을 계속 유지하지 않는 UX 진단 실행이 종료 코드 0으로 완료됐습니다. 리드가 축소 이미지 편집기의 색상 견본 6개와 동영상 편집기의 미리보기·전송 제어·상태 표시, 도움말 줄바꿈을 확인했습니다. 앞선 렌더에서 발견한 관련 결함은 수정됐습니다.

실제 모니터는 3440×1440 및 1366×768로 모두 96 DPI입니다. 144/192 DPI 산출물은 오프스크린 출력 밀도 검증이며 실제 혼합 DPI 모니터 조작 검증을 의미하지 않습니다. 네이티브 Pin 창은 `[0,0]`, `[3200,1308]`, `[3440,0]`, `[4566,636]`의 네 목표 위치에 모두 도달했습니다.

실제 포인터 드래그는 `[3200,100] → [3390,100] → [3580,100] → [3390,100] → [3200,100]`으로 두 번째 모니터에 완전히 진입한 뒤 원래 모니터로 복귀했습니다. 리드가 좌표를 독립 확인했습니다. `artifacts/validation/ux-review-v1.7.0-pointer-fixed`의 `native-pointer-validation.md`, `pin-input-events.txt`, `pin-secondary-monitor.png`, `pin-returned-primary.png`에 근거가 있습니다. 이벤트 처리 시점의 전역 커서 위치 대신 MouseDown 이벤트의 로컬 위치와 DPI로 앵커를 계산하도록 수정하여 지연 입력의 앵커 오류를 해결했습니다.

실제 Ctrl+C 입력은 `artifacts/validation/ux-review-v1.7.0-pointer/pin-input-events.txt`의 16:00:24 UTC `IMAGE identity=True; modifiers=Control`로 이미지 복사 이벤트와 원본 식별을 확인했습니다. 검증 fixture는 사용자 클립보드를 변경하지 않도록 복사 콜백을 대체했으므로 실제 클립보드 쓰기까지 검증한 것은 아닙니다. 네이티브 Ctrl+더블클릭은 도구의 modifier 유지 제약으로 실행하지 않았고 회귀 테스트로 확인했습니다. 대화형 진단 프로세스는 검증 후 종료했으며 이를 정상 종료 코드 0으로 주장하지 않습니다.

`artifacts/validation/ux-review-v1.7.0-native/gallery-native-caption.png`에서 실제 어두운 네이티브 제목 표시줄, 제목·버튼 정렬과 캡션 드래그를 확인했습니다. 이는 WPF 콘텐츠 렌더와 별도의 네이티브 검토입니다.

## 통합 및 산출물 계약

보안 분석 후 `--selftest-ux-review` 출력 경로를 현재 작업 디렉터리의 `artifacts/validation` 또는 임시 디렉터리의 `mycapture-ux-review`와 각각의 하위 경로로 제한했습니다. 쓰기 전에 정규화된 경로의 경계와 기존 상위 경로의 reparse point를 확인합니다. 허용 영역을 벗어나는 경로·유사 접두사 형제 경로·경계 밖 traversal은 거절하며 잘못된 출력 경로는 종료 코드 2로 처리합니다. 제한 검증 11개와 최종 전체 테스트 759개는 통과했지만, CodeQL 통과는 수정된 정확한 새 head의 결과를 별도로 확인해야 합니다. 수정 후 허용 경로 진단 실행도 `artifacts/validation/ux-review-v1.7.0-confined`에서 종료 코드 0, 보고서 PASS로 완료했습니다. 레이아웃 변경은 없으며 이 실행을 새로운 시각 검토로 주장하지 않습니다.

원격 ruleset 읽기 결과: 선형 이력 필수, PR 통합은 squash/rebase 허용, 필수 승인 0개, 최신 base 기준 `Release build and tests` 필수. 따라서 PR의 최신 head 검증 후 squash 통합하며, merge commit을 만들지 않습니다. 실제 실행과 결과는 아직 대기입니다.

최종 `build/package.ps1 -Version 1.7.0`은 source commit과 clean-tree 상태를 시작·종료 시 검증해야 합니다. 패키지 self-test는 독립 프로세스마다 종료 코드 0과 정확히 한 줄의 `RESULT: PASS`를 요구합니다. 최종 산출물 목록:

- `MyCapture-1.7.0-win-x64-setup.exe`
- `MyCapture-1.7.0-win-x64-portable.zip`
- `installer-manifest.json`
- `release-manifest.json`
- `SHA256SUMS.txt`
- `README-OFFLINE.txt`

소스 동결 이후의 태그 SHA, 통합 SHA, release URL, 각 asset 이름·크기·SHA-256 및 원격 실행 결과는 GitHub v1.7.0 릴리스 본문과 `artifacts/validation`의 릴리스 증거에 기록합니다. 검증된 패키지의 source SHA가 다시 바뀌지 않도록 해당 사후 결과를 이 소스 문서에 역으로 끼워 넣지 않습니다. 현재 체크섬이나 게시 성공을 미리 기입하지 않습니다.

## 알려진 제한과 검증 범위

- VS Code HTML은 지원하는 안전한 부분집합만 렌더링합니다. 실제 VS Code/Excel GUI와 서로 다른 DPI의 실제 모니터 조작은 별도 확인 여부를 기록해야 합니다.
- OCR 인식률은 Windows 언어 팩과 원본 픽셀에 영향을 받습니다. OCR을 사용할 수 없거나 인식할 텍스트가 없으면 자동 색인이 문자를 만들어내지 않습니다.
- 7일 만료는 라이브러리 이미지에만 적용합니다. 핀/활성 편집 보호, 기존 개수·용량 상한과 별도 저장 파일 보존은 구분합니다.
- 스크린샷 렌더는 실제 WPF 콘텐츠 검토에 쓰며, DWM 네이티브 제목 표시줄이나 실제 모니터 경계 조작을 검증한 것으로 대체하지 않습니다.
- Agy 읽기 전용 분석은 병렬 작업 중 원본 checkout 변경으로 wrapper에서 거절되었습니다. 해당 결과는 채택하지 않았고 같은 호출을 재실행하지 않았습니다.
