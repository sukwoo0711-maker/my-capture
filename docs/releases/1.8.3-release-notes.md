# MyCapture 1.8.3

설치 후 실행 무응답으로 보이는 문제, Explorer 트레이 복구와 이미지 메모리 관리를 개선하고 정밀 선택·빠른 갤러리·용량 절감 내보내기를 추가했습니다.

- 일반 실행은 라이브러리 창을 표시합니다. 로그인 자동 실행은 `--background`로 조용히 시작하며 기존 Run 등록도 이전됩니다.
- 첫 실행의 초기화가 오래 걸려도 두 번째 실행의 활성화 요청을 잃지 않도록 신호를 먼저 준비합니다. 이미 실행 중인 앱에 전경 활성화 권한을 전달합니다.
- Explorer 브로드캐스트를 받는 숨은 최상위 창으로 트레이를 관리합니다. 트레이 클릭·더블클릭과 메뉴 작업은 Explorer의 네이티브 콜백이 반환된 뒤 처리합니다.
- 다른 위치의 포터블/설치형이 실행 중이면 설치가 파일 교체 전에 종료 안내를 표시합니다. 사용자 세션을 임의 종료하지 않으며, 성공한 일반 설치는 앱을 실행합니다.
- 작은 영역 캡처는 선택된 픽셀만 보유합니다. 기존 전체 화면 비트맵 참조가 작은 핀에 남지 않습니다.
- 세로로 긴 썸네일은 긴 변 기준으로 축소하고 작은 이미지를 확대하지 않습니다. 예를 들어 16×320 썸네일을 320×6400으로 확대하던 경로를 제거했습니다.
- 갤러리 디코딩 캐시는 최대 16 MiB/64장으로 제한하며 갤러리를 숨기면 바인딩된 썸네일 참조도 해제합니다. 화면에 표시 중인 이미지와 활성 편집 원본은 필요한 동안 유지됩니다.
- 녹화 영역 선택은 화면을 백그라운드에서 읽고, 영역 확정 시 불필요한 이미지 잘라내기를 생략합니다. 선택 취소 후 늦은 캡처 결과가 창을 다시 열지 않습니다.
- 캡처·녹화 선택 화면에 대비가 높은 십자선과 고정된 시작점 표시를 추가했습니다. Shift를 누르면 포인터 이동량을 1/5로 줄여 픽셀 단위로 정밀하게 선택할 수 있습니다.
- 갤러리 썸네일은 최대 두 개씩 백그라운드에서 디코딩합니다. 편집 원본 준비도 UI 스레드 밖에서 한 번에 하나씩 처리하며, 로딩 중 닫기·갱신 시 오래된 결과를 버립니다.
- 갤러리 휠 입력을 가로채던 안쪽 스크롤 컨트롤을 제거하고 픽셀 단위 스크롤을 적용했습니다. 화면 밖 행의 가상화는 유지합니다.
- 편집기 저장 메뉴 또는 갤러리 이미지의 더보기 메뉴에서 **용량 줄여 내보내기…**를 선택할 수 있습니다. 기본은 원본 PNG이며, 1–90% 목표 절감률을 선택하면 실제 용량·절감률과 미리보기를 계산합니다. 결과를 저장하거나 **폴더로 드래그** 버튼을 끌어 복사할 수 있습니다.
- 용량 절감은 원본 PNG 바이트 수를 기준으로 계산합니다. 불투명 이미지는 JPEG 품질을 조절하되 픽셀 크기를 유지하며, 목표에 못 미치면 실제 결과를 표시합니다. 투명 이미지는 투명도를 유지하는 PNG로 내보냅니다. 갤러리 보관 원본과 일반 저장·클립보드의 품질은 유지됩니다.

설치형과 포터블은 동일한 앱·런타임 payload를 사용합니다. 설치형의 제거 파일, 소유권 기록, 시작 메뉴 등록은 의도된 차이입니다. 포터블 앱 내 업데이트는 일반 설치형 전환이므로 포터블 유지 시 새 ZIP을 별도 폴더에 풀어 사용하세요.

실제 작업 관리자 RAM 감소율이나 사용자 환경에서의 Explorer 정지 재현 해결을 측정한 릴리스는 아닙니다. 코드상의 원인과 회귀 테스트, 패키지 검증 결과를 [검증 기록](1.8.3-validation.md)에 구분해서 기록합니다.
