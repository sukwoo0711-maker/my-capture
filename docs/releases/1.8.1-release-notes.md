# MyCapture 1.8.1

> 이 문서는 패치의 변경 범위를 설명합니다. 실제 배포 커밋·파일·검증 결과는 [GitHub 릴리스](https://github.com/sukwoo0711-maker/my-capture/releases)의 검증 기록을 확인하세요.

1.8.1은 영역 캡처 단축키를 누르는 순간 발생하는 멈춤 현상을 다룹니다. 기존 경로에서는 선택 화면을 열기 전에 전체 가상 데스크톱의 픽셀을 UI 스레드에서 동기적으로 읽었습니다. 이 과정에서 큰 임시 이미지 버퍼를 할당하고 복사하는 비용도 확인했습니다.

- 전체 데스크톱 이미지 획득을 작업 스레드로 옮겨, 캡처 준비 중에도 UI 디스패처가 다른 입력과 화면 작업을 처리할 수 있게 했습니다. 선택 화면은 새로 획득한 고정 이미지가 준비된 뒤에 표시합니다.
- 단축키를 연속으로 눌러도 동시에 하나의 캡처만 준비합니다. 취소 후에는 진행 중인 네이티브 캡처가 끝날 때까지 새 캡처를 막고, 늦게 도착한 결과를 버립니다. 앱 종료 후에도 선택 화면이 다시 열리지 않습니다.
- 이미지 획득 실패는 UI에서 알리고 다시 시도할 수 있습니다. 녹화 중 캡처 제외 처리는 선택 화면을 표시하기 직전에 다시 확인합니다.
- 캡처 요청, 이미지 획득 완료, 선택 화면의 첫 렌더링 시간을 로그에 기록합니다. 이미지 픽셀이나 사용자 텍스트는 이 진단 로그에 기록하지 않습니다.

큰 임시 버퍼와 전체 이미지 복사를 줄이는 직접 읽기 경로도 함께 검증하고 있습니다. 비동기 처리와 직접 읽기를 통합한 실제 단축키 반응 시간, 할당량, 전체 캡처 시간은 최종 후보에서 확인해야 합니다. 이 문서는 특정 속도 향상 배율이나 멈춤 현상의 완전한 해소를 보장하지 않습니다.

Windows 지원 범위, 오프라인 설치·포터블 배포, 기존 캡처·편집 데이터 형식은 [1.8.0](1.8.0-release-notes.md)의 범위를 유지합니다. 패치 검증 절차는 [1.8.1 검증 문서](1.8.1-validation.md)에 설명합니다.

## English overview

The region-capture hotkey previously acquired the entire virtual desktop synchronously on the UI thread, with a large temporary image allocation and copy. Frame acquisition now runs on a worker thread while a single active session prevents overlapping requests. Cancellation and shutdown discard late results; failure feedback and recording-exclusion checks remain on the UI dispatcher.

Direct readback to reduce the temporary buffer and copy is also under validation. Final integrated measurements are still required before claiming an improvement in total capture time or elimination of stutter. Diagnostic logs separate acquisition and first-render timing without recording image pixels or user text.
