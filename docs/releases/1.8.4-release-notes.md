# MyCapture 1.8.4

캡처 시작 시 화면이 검게 깜박이는 문제와 영역 선택 중 불필요한 렌더링·메모리 사용을 개선했습니다.

- 캡처·녹화 영역 선택창은 배경 이미지가 준비된 뒤 표시합니다. 이미지가 없는 검은 창을 먼저 띄우던 순서를 수정했습니다.
- 마우스를 움직일 때 고정된 전체 화면 배경을 다시 구성하지 않고 포인터와 선택 영역을 갱신합니다. 확대경은 입력을 화면 갱신 주기로 모아 처리하며 작은 픽셀 버퍼를 재사용합니다.
- 작은 영역을 편집하는 동안 전체 모니터 이미지까지 보관하던 참조를 제거했습니다. 촬영 위치, 모니터, DPI 정보는 유지합니다.
- 선택창을 닫으면 배경 이미지, 확대경, 렌더링 이벤트 참조를 해제합니다.
- 이미지 저장·합성용 STA 작업 스레드가 끝날 때 WPF Dispatcher도 종료해 네이티브 렌더링 자원을 정리합니다. 반복 작업에서 증가하는 핸들 수를 줄였습니다.
- 실행 취소·다시 실행으로 복구 가능한 삽입 이미지는 유지하고, 폐기된 기록에서 더 이상 사용하지 않는 이미지는 메모리에서 해제합니다.
- Shift 정밀 이동, 원본 품질 기본 내보내기, 선택적 용량 절감 기능은 유지됩니다.

성능 검증 조건과 수치는 [검증 기록](https://github.com/sukwoo0711-maker/my-capture/blob/main/docs/releases/1.8.4-validation.md)에 기재합니다. 합성 화면의 반복 측정과 실제 장치의 체감 성능은 구분하며, 강제 GC나 작업 집합 축소를 제품 동작에 추가하지 않았습니다.

Windows 11 x64용 설치판과 포터블 ZIP을 제공합니다. 설치판은 `MyCapture-1.8.4-win-x64-setup.exe`, 포터블은 `MyCapture-1.8.4-win-x64-portable.zip`을 사용하세요.

최종 검증: Release 테스트 1,010개, PR 및 main CI/CodeQL, 설치·업데이트 검사, 네이티브 진단 7종을 통과했습니다. 최초 패키지 검증에서는 녹화된 첫 MP4 재열기가 실패했으며, 코드·제한 시간·검증 조건을 바꾸지 않은 동일 커밋의 두 번째 실행에서 전체 통과했습니다. 최초 실패의 원인은 확정하지 않았습니다.
