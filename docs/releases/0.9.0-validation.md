# MyCapture 0.9.0 릴리스 검증

검증 상태: **PASS**
검증 시각: 2026-08-30 UTC
기준선: `main@76d402d`, MyCapture 0.7.0
검증 대상: 변경이 적용된 로컬 worktree와 그 worktree에서 생성한 0.9.0 산출물

## 1. 릴리스 범위

0.9.0은 동영상 편집기의 pointer intent, timeline rendering, decoder seek를 서로 다른 cadence로 분리한다.

- 세 timeline surface에 고정 `DrawingVisual` 3개씩, 전체 9개
- dirty layer만 composition frame에서 갱신
- nullable capacity-one latest-wins preview queue
- 최대 decoder seek in-flight 1 + pending 1
- 45ms preview sampling, release `Exact` 우선, generation stale suppression
- `MediaElement` 호출을 pointer stack 밖의 dispatcher adapter로 격리
- encoder warm-up 중 빠른 Stop에도 timestamp-zero frame 보장
- 실제 MF MP4/실제 WPF 창을 사용하는 `--selftest-video-editor`
- 새 production package 없음; Flyleaf/FFmpeg/Skia/VLC 미도입

버전은 다음 세 위치에서 일치한다.

- `Directory.Build.props`: `Version=0.9.0`, `FileVersion=0.9.0.0`, `AssemblyVersion=0.9.0.0`
- `src/MyCapture.App/app.manifest`: `assemblyIdentity version="0.9.0.0"`
- 최종 `MyCapture.dll`: ProductVersion `0.9.0`, FileVersion `0.9.0.0`

명시적 방향 회귀는 `MediaFoundationEncodeRoundTripTests.Encode_PreservesOrientation_NoVerticalFlip_NoHorizontalMirror`다.

전체 suite 중 timing test가 한 번 `second preview dispatched too soon: 0.7ms`로 실패했다. 분석 결과 구현 interval이 아니라 첫 worker 완료 후 두 번째 요청 완료까지를 측정해 scheduler 선점에 민감한 테스트였다. 실제 engine dispatch timestamp 간격을 측정하도록 수정했고, Exact 요청이 preview delay 등록 직전에 들어오면 cancellation을 놓칠 수 있던 lock gap도 함께 제거했다. 수정 후 해당 test 독립 프로세스 20/20과 전체 424/424가 통과했다.

실제 MF recorder는 encoder 초기화가 700ms test window보다 길 때 sample 0개로 finalize될 수 있었다. 오류는 `MF_E_SINK_NO_SAMPLES_PROCESSED (0xC00D4A44)`였으며 수정 전 실제 test 3/3 실패, timestamp-zero frame 보장 수정 후 3/3 통과했다. `StopDuringEncoderWarmup_StillWritesTimestampZeroFrame`이 이 경로를 deterministic하게 고정한다.

## 7. Windows 호환성과 남은 한계

보존된 정적 계약:

- TFM: `net10.0-windows10.0.19041.0`
- `SupportedOSPlatformVersion`: `10.0.17763.0`
- platform/runtime: x64 / win-x64
- manifest Windows 10/11 supportedOS GUID 유지
- installer/release manifest minimum build 17763
- setup/portable 모두 self-contained 및 offline

실기기 성능 검증 host는 Windows build 26200이다. 이번 세션에는 Windows 10 1809 실제 장비가 없었으므로 build 17763에서의 물리 실행은 검증하지 못했다. 1809 보존 근거는 API analyzer/build 성공, `SupportedOSPlatformVersion`, app manifest, installer preflight/manifest 계약이다. Windows 10 1809 실제 장비 smoke는 배포 채널의 최종 호환성 확인 항목으로 남는다.

또한 setup은 Authenticode 미서명이다. `README-OFFLINE.txt`가 unknown-publisher 경고와 trusted channel을 통한 SHA-256 확인 필요성을 명시한다. 이 검증은 코드 서명을 대체하지 않는다.

MediaElement는 true exact-frame/presented-timestamp 계약을 제공하지 않는다. 0.9.0은 interaction responsiveness와 stale suppression을 통과했지만 Flyleaf 승격 기준인 exact-frame correctness 비교를 수행한 것은 아니다. Flyleaf와 FFmpeg는 production dependency에 포함하지 않았다.
