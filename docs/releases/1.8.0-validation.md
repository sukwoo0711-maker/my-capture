# 1.8.0 release validation runbook

This is an operator runbook, not a record of passing release gates. Keep exact commands, exit codes, reports, source commits, and package hashes with the final release evidence. A timeout, skipped test, pending check, or process launch without its required report is not a pass.

## Source and package provenance

1. Complete review and required checks on the final PR head. After authorized integration, fetch and verify the exact `origin/main` commit and the clean local worktree used for packaging. Do not package the isolated development worktree as the final release.
2. Verify MSBuild product version `1.8.0`, file/assembly/Windows manifest version `1.8.0.0`, and default package/installer-test version `1.8.0`.
3. Run the repository's full Release validation, then package from that verified clean main:

   ```powershell
   powershell.exe -NoProfile -ExecutionPolicy Bypass -File build/build.ps1 -Configuration Release -Test
   powershell.exe -NoProfile -ExecutionPolicy Bypass -File build/package.ps1 -Version 1.8.0
   ```

4. Check `artifacts/release/1.8.0/release-manifest.json`: `SourceCommit` must equal the verified main SHA, `SourceTreeClean` must be `true`, and version/runtime/inventories must match the candidate. Recompute `SHA256SUMS.txt` entries. The setup and portable ZIP remain unsigned; hashes do not independently establish publisher identity.
5. The release tag must resolve to that same source commit. Recheck the tag/main relationship and artifact hashes immediately before the separately authorized publication. If source changes, rerun required exact-head checks and regenerate the artifacts; do not relabel old artifacts.

The packaged runner covers `--selftest-capture`, `--selftest-shell`, `--selftest-advanced`, `--selftest-settings`, `--selftest-ocr`, `--selftest-recording`, and `--selftest-video-editor`. Follow its existing requirement to close resident MyCapture instances before the complete seven-test suite; the shell diagnostic exercises real hotkeys. Each requires exit zero and the exact expected report result.

Separate performance diagnostics are `--selftest-recording-performance <output-directory>` and `--selftest-pin-storage-performance <output-directory>`. Use distinct owned output directories and an agreed quiet measurement window. Their synthetic results and uncontrolled workstation load must remain explicit. `--selftest-ux-review` creates its own temporary fixture directory and prints `UX_REVIEW_OUTPUT=...`; it is not a replacement for native pointer, keyboard, minimum-size, or DPI review.

## Real packaged update and isolated diagnostic restart

The following harness defaults to preflight only. Supply the candidate's exact recorded source SHA and an available repository-pinned .NET SDK executable:

```powershell
$candidateSha = '<verified 40-character source SHA>'
$sdk = 'C:/Users/sukwo/AppData/Local/MyCapture/dotnet-sdk/dotnet.exe'
powershell.exe -NoProfile -ExecutionPolicy Bypass -File build/tests/update-restart-acceptance.ps1 -ArtifactRoot artifacts/release/1.8.0 -ExpectedSourceCommit $candidateSha -DotNetPath $sdk
powershell.exe -NoProfile -ExecutionPolicy Bypass -File build/tests/update-restart-acceptance.ps1 -ArtifactRoot artifacts/release/1.8.0 -ExpectedSourceCommit $candidateSha -DotNetPath $sdk -Execute
```

Preflight verifies package checksums, clean source provenance, payload inventory, and seed installer source against the candidate bootstrap inventory. Execution then:

- Extracts the actual `MyCapture.UpdateHelper.ps1` embedded resource from the verified candidate DLL with a bounded metadata-only reader; it never loads that assembly into the reader process.
- Seeds a GUID-owned installation below `artifacts/validation/update-restart` using the verified installer source with `-NoShellIntegration`.
- Creates only a fresh version/GUID session under the installer's required `%LOCALAPPDATA%/MyCapture/Updates` parent. It does not update the resident installation or sweep the session parent.
- Runs the unchanged embedded helper main body, actual packaged IExpress setup, installer receipt checks, installed binary hashes/version checks, and real three-second restart liveness check.
- Uses the existing `Start-UpdateProcess` test seam only to select the fixed `--selftest-ux-review` switch on the same verified installed executable. It returns a real process, captures the receipt before helper cleanup, and requires the real diagnostic process to exit zero with a passing WPF fixture report in the owned temporary directory.

The final line must be `RESULT: PASS (real packaged update and diagnostic restart; resident startup remains outside this harness)`, with exit zero and `acceptance-result.json` containing `Result: PASS`. Retain `acceptance-owner.json`, `verified-install-result.json`, `restart-process.json`, stdout/stderr, seed log, diagnostic reports, hashes, and `SourceCommit` as evidence. The GUID-owned installation and evidence remain for inspection; the helper alone performs its normal exact-session cleanup. A timeout retains evidence and stops only the harness worker and its recorded diagnostic after matching process start time and owned executable path. It does not claim success or kill unrelated application processes. Inspect the retained installer log/session before removing a timed-out installation; an independently running IExpress child is not a successful completed install.

This proves actual installation and actual binary startup in diagnostic mode. It does **not** prove normal resident-tray startup, live-user settings migration, hotkey registration, physical input latency, or mixed-DPI hardware behavior. It also does not exercise the application's UI shutdown callback; that retains its separate lifecycle tests. Do not publish a broader claim based on this harness.
