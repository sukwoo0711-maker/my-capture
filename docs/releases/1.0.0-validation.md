# MyCapture 1.0.0 릴리스 검증

검증 상태: **PASS**
검증 시각: 2026-08-31 UTC
기준선: `release/0.9.0@26c0187`, MyCapture 0.9.0
검증 대상: `release/1.0.0@0795d60`과 그 커밋에서 생성한 1.0.0 산출물
검증 호스트: `Microsoft Windows NT 10.0.26200.0`, x64

## 1. 릴리스 범위

1.0.0은 기능 릴리스가 아니라 **지원 범위와 배포 계약을 확정하는 릴리스**다.

- 호스트 지원 하한을 Windows 11 21H2(build 22000)로 올리고 Windows 10을 지원 대상에서 제외
- 하한의 단일 출처를 `MyCapture.Core.Platform.WindowsSupportPolicy`로 통일
- 포터블 ZIP은 installer를 거치지 않으므로 프로세스 자체가 하한을 강제하는 `HostRequirementGate` 추가
- self-contained·offline 배포를 전용 publish profile로 명시화
- packaging이 prerelease를 포함한 SemVer를 받되 Win32 file version은 숫자만 사용
- 주석 편집기 기본 도구를 연필로 변경하고 자유곡선을 연속 모드로 전환
- 설정 self-test의 진단 핫키를 충돌하지 않는 chord로 탐색

production dependency 추가는 없다. 앱 package graph는 0.9.0과 동일하게 top-level `Microsoft.Extensions.DependencyInjection`/`Logging`/`Logging.Debug` 3개다.

## 2. 버전 계약

세 위치가 일치한다.

- `Directory.Build.props`: `Version=1.0.0`, `FileVersion=1.0.0.0`, `AssemblyVersion=1.0.0.0`
- `src/MyCapture.App/app.manifest`: `assemblyIdentity version="1.0.0.0"`
- 최종 `MyCapture.dll`: ProductVersion `1.0.0+0795d60a101bc63377b311d3d1e590d80fb0ecd5`, FileVersion `1.0.0.0`

플랫폼 계약도 세 위치가 일치한다.

- `Directory.Build.props`: TFM `net10.0-windows10.0.22000.0`, `SupportedOSPlatformVersion=10.0.22000.0`
- `WindowsSupportPolicy.MinimumBuild`: `22000`
- release manifest `Compatibility.MinimumWindowsBuild`: `22000`

`package.ps1`과 `installer-hostile-tests.ps1`의 기본 `-Version`은 GA인 `1.0.0`이다. `-Version`을 잊어도 prerelease가 배포되지 않으며, prerelease 문자열 자체는 여전히 파싱된다. `ReleaseVersionContractTests`가 이 두 성질을 함께 고정한다.

## 8. installer 및 setup.exe 딜리버러블

### hostile suite

```text

```

19.2초에 13개 케이스가 통과했다. exact package inventory/version/forward-slash ZIP, verify-only, corrupt payload rejection, traversal 및 case-insensitive duplicate rejection, unowned root 보존, disk preflight, installer/uninstaller mutex, Unicode install path, backup/commit fault rollback, 외부 user data 보존을 포함한다.

### setup.exe end-to-end

hostile suite는 `install.ps1`을 payload와 직접 구동하므로, 사용자가 실제로 실행하는 IExpress wrapper 자체를 별도로 검증했다.

## 9. 남은 한계

배포 전에 명시적으로 인지해야 하는 항목이다.

1. **Authenticode 미서명.** release manifest가 `Unsigned: true`이고 `package.ps1`에 서명 단계가 없다(`CAB_ResvCodeSigning=0`). Windows가 알 수 없는 게시자 경고를 표시한다. `README-OFFLINE.txt`가 이 사실과 SHA-256 확인 필요성을 명시하지만, 해시는 우발적·악의적 변경을 탐지할 뿐 게시자 신원을 증명하지 않는다.
2. **Windows 11 21H2(build 22000) 실기기 미검증.** 검증 호스트는 build 26200 하나다. 하한은 `WindowsSupportPolicy`, `HostRequirementGate`, installer preflight, release manifest 네 곳에서 강제되고 단위 테스트가 22000 수용/17763 거부를 고정하지만, 물리적 22000 호스트에서의 실행은 확인하지 못했다. 배포 채널의 최종 호환성 확인 항목으로 남는다.
3. **현지화 리소스 0개.** `.resx`/`.resw`가 없고 UI 문자열이 한국어로 하드코딩돼 있다. 영어·일본어 UI는 없다.
4. **녹화 오디오 없음.** 마이크·시스템 오디오 경로가 구현돼 있지 않다.
5. **라이선스·가격 모델 없음.** 라이선스 검증이나 기능 잠금 코드가 없다.
6. **온보딩 없음.** `GeneralSettings.IsFirstRun`이 저장·복원되지만 이를 소비하는 최초 실행 UX가 없다.
7. **`MediaElement` exact-frame 한계.** 0.9.0에서와 동일하다. 상호작용 반응성과 stale suppression은 통과했으나 exact-frame correctness 비교를 수행한 것은 아니다. Flyleaf/FFmpeg는 production dependency에 포함하지 않았다.
8. **참조 프로젝트 PDB 3개 동봉.** publish profile이 `DebugType=None`을 지정하지만 이는 앱 프로젝트에만 적용되어 `MyCapture.Core.pdb`, `MyCapture.Ocr.pdb`, `MyCapture.Platform.pdb`가 패키지에 포함된다. 기능·보안 영향은 없으나 1.0.1 정리 대상이다.
9. **OCR 문자 혼동.** `ko` 언어팩에서 소문자 `l`을 대문자 `I`로 읽어 `Hello`→`HeIIo`, `World`→`WorId`가 됐다. OS `Windows.Media.Ocr` 엔진의 특성이며 self-test 게이트는 통과했다. 전문 검색 결과 품질에 영향을 줄 수 있다.

## 10. 최종 판정

1.0.0은 현재 검증 환경에서 **릴리스 gate PASS**다.

- 461/461 테스트 PASS, build warning 0
- 버전·플랫폼 계약이 선언된 모든 위치에서 일치
- 포터블 실기기 self-test 5종 전부 PASS, video-editor 성능 게이트 전 항목 PASS
- 50회 same-process 편집기 lifecycle과 16MiB/20MiB 메모리 게이트 PASS
- .NET 미설치 상황을 모사한 오프라인 실행에서 번들 런타임 로드 확인
- installer hostile 13/13, setup.exe 딜리버러블 7 게이트 전부 PASS
- 사용자 기존 설치 환경 무영향

Authenticode 서명과 Windows 11 21H2 실기기 smoke는 **배포 리스크로 남는다.** §9의 3–6번 항목은 유료 배포 전 별도 작업이 필요하다.
