# ADR 0010 — 그림 핀의 네이티브 창

상태: 채택 — 기본값은 꺼짐, 150 % 배율 확인과 릴리스 성능 관문 대기
기준: MyCapture 5.3.0, `feat/pin-organize`(#256·#259) 위의 1단계
관련: [ADR 0008](0008-powershell-free-installer.md)

## 배경

그림 핀 하나는 WPF 창, 그림의 `BitmapSource`, WPF 렌더 대상과 드라이버 캐시를 함께 보유합니다. 개발 PC에서 1600x1000 그림 핀 하나가 약 40.6 MB, 3840x2160 그림 핀 하나가 약 235 MB를 차지했습니다. 핀을 여러 개 띄워 두는 사용 방식에서 이 비용이 상주 메모리의 대부분이었고, 첫 프레임과 휠 확대 반응도 WPF 레이아웃과 렌더 경로의 영향을 받았습니다. 핀 자체는 그림을 보여 주고 옮기고 확대하는 일이 대부분이어서, 그 경로만 WPF 없이 그릴 수 있는지 시험했습니다.

## 결정

그림 핀만 `NativePinWindow`(레이어드 HWND 하나, 그림 원본 하나, 화면에 보이는 부분의 DIB 하나)로 띄울 수 있게 합니다. 설정 **그림 핀을 적은 메모리로 띄우기**(`PinSettings.LightweightImagePins`, 기본 꺼짐)를 켰을 때만 새로 띄우거나 다시 여는 핀에 적용합니다.

- 사용자·세션·`PinManager`·트레이·시험이 다루는 객체는 계속 `PinWindow`입니다. `PinWindow`는 핀의 정체성, 내용, 보기 상태, 명령, 이벤트를 가진 논리 핀이고, 표시는 두 호스트 중 하나가 맡습니다. 네이티브 호스트(`NativePinHost`)가 표시하는 동안 `PinWindow`의 WPF 창은 보이지 않으며 `HwndSource`와 렌더 대상도 만들어지지 않습니다.
- 호스트 선택은 순수 함수 `PinHostPolicy.Choose`가 합니다. 설정이 켜져 있고, 스크린 리더가 없고, 접히지 않았고, 원문·번역 덧씌움·Mermaid 결과가 없는 일반 그림일 때만 네이티브입니다.
- 마우스를 올리면 나타나는 도구 막대, 하단 안내 메시지, 클릭 통과 손잡이, 착지 장식 같은 부속 WPF 창은 `IPinAnchor`로 두 호스트에 같은 방식으로 붙습니다.

## 호스트 전환 규칙

네이티브 핀은 WPF 창으로 **한 번 바뀌고 다시 돌아가지 않습니다.** 같은 `PinWindow` 객체 안에서 바뀌므로 목록, 사전, 이벤트 구독, 트레이 항목, 세션 식별이 달라지지 않습니다. 전환은 WPF 창을 네이티브 창 바로 아래에 그리고, WPF가 첫 프레임을 그린 뒤에 네이티브 창을 닫는 순서로 해서 빈 순간이 없게 합니다. 닫히는 중인 핀은 전환하지 않습니다.

전환 조건은 다음과 같습니다.

- 글자 선택(`F2`, 메뉴), 번역, 접기(`Shift+더블클릭`, 메뉴)처럼 WPF 창만 가진 기능을 시작할 때.
- 스크린 리더가 시작될 때. `SystemParametersInfo(SPI_GETSCREENREADER)`를 시작할 때 읽고, 앱의 메시지 창이 `SPI_SETSCREENREADER`가 담긴 `WM_SETTINGCHANGE`를 받을 때 다시 읽습니다(`ScreenReaderState`). 열려 있는 네이티브 핀은 모두 전환하고 이후 새 핀은 WPF로 열립니다. 이 값은 보조 프로그램이 스스로 올리는 표시이므로 표시하지 않는 프로그램은 놓치고, 비정상 종료한 프로그램이 값을 남겨 두면 핀이 WPF에 머뭅니다(안전한 쪽). UI Automation 클라이언트 수신 여부는 자동화 도구만 붙어도 참이므로 이 판단에 쓰지 않습니다.
- 설정을 끌 때. 열려 있는 네이티브 핀이 모두 즉시 전환되어 설정을 끈 상태는 이전 동작과 같습니다. 켤 때는 이후에 새로 띄우거나 다시 여는 핀에만 적용하고 열려 있는 WPF 핀은 그대로 둡니다.
- 네이티브 창이 만들어진 뒤 실패할 때. 만들 때의 실패는 WPF로 열고 경고를 프로세스당 한 번만 기록합니다.

다시 열기와 세션 복원은 정책을 처음부터 다시 거치므로 다음에는 네이티브일 수 있습니다.

## WPF에 남기는 것과 이유

텍스트·표·코드·Markdown·Mermaid 핀은 표시 배율과 확대에 맞춰 글자를 다시 그리고 그 보기가 WPF 시각 트리라서 네이티브로 옮기지 않습니다. 글자 선택, 그림 핀의 번역 덧씌움과 번역문 보기, 번역 진행 막대, 접힌 미리 보기도 각각 수백 줄 이상의 WPF 보기이고 쓸 때만 필요하므로 한 번 전환하는 쪽이 두 번째 구현보다 쌉니다. 스크린 리더가 실행 중이면 UI Automation 이름과 도움말을 가진 WPF 창만 쓰게 합니다.

## 그림 한 벌 규칙

네이티브 핀의 그림 원본은 미리 곱한 알파의 `NativePinPixelSource` 하나입니다. 모든 픽셀이 불투명한 그림은 이 원본이 원래 그림의 무손실 사본이므로 `PinPicture`가 `BitmapSource`를 놓아 두고, 복사·저장·닫은 핀 기록·세션 저장·전환처럼 사용자 동작이 있을 때만 원본에서 다시 만듭니다. 반투명 그림은 두 벌을 유지합니다. 사용자 동작이 없는 경로는 `content.PixelWidth`, `content.PixelHeight`, `content.Picture`를 읽고 `content.Image`를 읽지 않습니다.

## 화면에 맞춘 그림

확대한 핀의 표면 전체를 메모리에 두지 않고, 표면과 그 표면에 닿는 모니터들의 경계 상자가 겹치는 부분만 DIB와 HWND가 보유합니다(`NativePinRaster.View`). 한 모니터 안에서 그 모니터보다 작은 핀은 표면 전체이므로 이전과 같습니다. 바깥으로 알리는 값(`Bounds`, `PhysicalBounds`, 배치, 붙이기 대상, 복원 기록)은 언제나 표면 전체입니다. 모니터 구성이 바뀌면(`WM_DISPLAYCHANGE`) 보유 범위를 다시 계산합니다.

## 끌 때 붙이기

네이티브 핀을 끌 때도 #259와 같이 작업 영역과 다른 핀의 가장자리에 붙습니다(`PinSnap.Calculate`). 끌기를 시작할 때 대상을 한 번 읽고, 움직이는 핀과 대상 모두 표면 전체 사각형을 사용하며 `Shift`는 붙이기를 해제합니다. 대상은 호스트와 무관하게 보이는 핀 모두이므로 WPF 핀도 네이티브 핀에 붙습니다.

## 측정

개발 PC(3440x1440 + 768x1366, 둘 다 100 %)에서 같은 빌드로 설정만 바꿔 잰 값입니다. 메모리는 핀 10개를 띄웠을 때 늘어난 양을 핀 수로 나눈 것이며, 프로세스의 개인 커밋에 1 MiB 이상의 섹션을 더했습니다(네이티브 핀이 화면에 보이는 그림을 섹션으로 가지기 때문입니다).

| 항목 | 설정 끔 | 설정 켬 |
| --- | --- | --- |
| 1600x1000, 핀당 메모리 | 41.3 MB | 27.5 MB |
| 1920x1080, 핀당 메모리 | 51.3 MB | 30.8 MB |
| 3840x2160, 핀당 메모리 | 235.4 MB | 95.5 MB |
| 핀 10개를 닫은 뒤 남는 개인 커밋(1600x1000 / 3840x2160) | 340 / 735 MB | 26 / 22 MB |
| 1600x1000, 첫 프레임 | 39 ms | 21 ms |
| 3840x2160, 첫 프레임 | 141 ms | 52 ms |
| 휠 확대 한 단계, 1600x1000 (중앙값 / 최장) | 26 / 45 ms | 16 / 29 ms |
| 마우스를 올릴 때 도구 막대 표시 | 25 ms | 2 ms |
| 투명도 변경 한 번 | 3 ms | 8 ms |
| 텍스트 핀, 핀당 메모리 | 22.8 MB | 22.5 MB (변화 없음, 텍스트 핀은 WPF) |

## 알려진 한계

- 표시 배율 150 %와 배율이 다른 모니터 조합은 실제 하드웨어에서 확인하지 않았습니다. 개발 PC는 두 모니터 모두 100 %이며, 배율 경로는 배율 주입과 보낸 메시지로만 실행했습니다.
- Windows는 WPF 창이 가상 화면보다 커지는 것을 허용하지 않으므로, 가상 화면보다 크게 확대한 핀은 WPF로 전환한 뒤 잘립니다. 지금의 핀도 같은 한계를 가집니다.
- 기본값은 소유자의 150 % 확인과 릴리스 성능 관문이 끝날 때까지 꺼짐으로 둡니다.

## 대안

| 대안 | 이번 결정의 이유 |
| --- | --- |
| `PinWindow`를 `Pin`과 `WpfPinHost`로 쪼갬 | 시험 호출 약 200곳과 제품 호출 약 25곳이 `PinWindow`를 기대하고, 전환 때 목록·구독 17개를 다시 묶어야 합니다. 네이티브가 그림 핀 대부분을 맡게 되는 2단계에서 다시 판단합니다. |
| 전환 없이 모든 기능을 네이티브로 구현 | 글자 선택·번역·접기는 쓸 때만 필요한 큰 WPF 보기입니다. |
| 설정 없이 기본 적용 | 150 % 배율과 혼합 배율 확인이 끝나지 않았습니다. |
