# MyCapture 감성품질(UX·UI·사용성) 조사 요청

당신은 Windows 데스크톱 앱의 시니어 UX/UI 리뷰어입니다. 이 작업은 **조사와 제안만** 합니다. 파일을 수정하거나 빌드하지 마십시오. 보고서는 한국어로 씁니다.

## 대상
- 앱: MyCapture. Windows 11 전용 WPF(.NET 10) 화면 캡처 앱입니다. 영역·창 캡처, 주석 편집기, 핀(항상 위에 뜨는 이미지 창), OCR, 화면 녹화와 동영상 편집, 캡처 라이브러리(폴더·검색)를 제공합니다.
- 저장소 작업 루트: 현재 디렉터리(브랜치 `fix/realdevice-qa-round4`). UI 코드는 `src/MyCapture.App/` 아래에 있습니다. 공통 스타일은 `src/MyCapture.App/Themes/Controls.xaml`, `Tokens.xaml`, `Symbols.xaml`, 모션은 `Themes/FluidMotion.cs`, 화면 문구는 `src/MyCapture.Core/Localization/Strings.resx`에 있습니다.
- 화면 자료(현재 빌드로 렌더한 PNG): `artifacts/astra-ux-audit/inputs/`
  - `app-renders/`: 창별 렌더입니다. 테마는 midnight·daylight(normal)와 glass(compact)이고, 설정 페이지 7개도 있습니다.
  - `capture-guide/`: 캡처 오버레이의 첫 안내 카드, 창 강조, 드래그 상태입니다.
  - `library/`: 라이브러리의 폴더 화면, 검색 배지, 끌어 놓은 뒤 화면입니다.
  - `source-details/`: 라이브러리 상세 패널의 "출처" 섹션입니다.
  - `user-screenshots/`: 사용자가 실기 테스트에서 직접 지적한 화면입니다.

## 사용자가 실기 테스트에서 지적한 것 (맥락)
- "전반적으로 감성품질이 떨어진다."
- 폴더 화면의 "새 캡처를 이 폴더에 저장" 칩이 "매우 구리다". 지금은 토글 스위치로 바꿨지만 켜고 끌 때 애니메이션 없이 즉시 바뀝니다.
- 동영상 편집기 오른쪽 위 "라이브러리에 저장"과 "내보내기 · MP4 / GIF"는 위치가 반대로 느껴지고, 어느 쪽이 강조 버튼인지 헷갈립니다.
- 엑셀 셀을 복사해 F3(클립보드 핀)으로 띄우면 이상한 모양입니다(셀 텍스트를 다시 그린 격자).
- VS Code 코드를 핀으로 띄우면 창 모서리의 테두리가 끊겨 비어 보입니다(`user-screenshots/code-pin-corners.png`).
- 이전 라운드: 캡처 안내가 어렵다, 단축키 나열식 안내는 도움이 안 된다.
- 위 개별 항목은 이미 따로 고치는 중이니 원인 분석을 반복하지 마십시오. 이 조사의 목적은 **앱 전체에서 같은 종류의 문제를 체계적으로 찾고, 우선순위를 매긴 개선안을 내는 것**입니다.

## 조사할 관점
1. **시각 완성도**: 정렬, 여백 리듬, 모서리 반경, 테두리·구분선 일관성, 끊기거나 겹치는 선, 그림자, 아이콘 굵기와 크기 통일, 글꼴 크기·굵기 위계, 테마별 대비(특히 daylight·glass·고대비).
2. **모션과 마이크로 인터랙션**: 상태 전환(토글, 선택, 호버, 누름, 창 열기·닫기, 토스트), 지속 시간과 이징의 일관성, 애니메이션이 없어 "딱딱하게" 느껴지는 곳. 시스템의 애니메이션 줄이기 설정을 따라야 합니다.
3. **버튼과 명령의 위계**: 주 동작과 보조 동작의 강조 방식, 배치 순서가 화면마다 일관된지. 이미지 편집기는 [파일로 저장][복사][완료(강조)][취소] 순서입니다.
4. **사용성**: 처음 쓰는 사람의 이해, 발견 가능성, 피드백(진행·완료·오류), 키보드와 접근성.
5. **문구 톤**: 레이블은 명사형, 문장은 합니다체를 씁니다. 해요체, 느낌표, 감탄사, 이모지는 쓰지 않습니다. 이 규칙에 어긋나는 곳이 있으면 지적하십시오.
6. **비교 기준**: Windows 11 Fluent 디자인(WinUI 3 컨트롤의 모양과 모션)과 Snipping Tool, Snipaste, PixPin, ShareX, Snagit에서 사용자가 기대하는 관례와 비교하십시오. 외부 자료를 참고했다면 출처를 적고, 기억에 의존했다면 그렇다고 밝히십시오.

## 보고서 형식 (마크다운)
1. **총평**: 3~5줄
2. **우선순위 목록**: 최대 20개, P0/P1/P2. 항목마다 다음을 적습니다.
   - 화면과 상황
   - 근거: PNG 경로와 위치, 또는 `파일:줄`
   - 감성품질을 해치는 이유
   - 구체적 개선안: 여백·반경·지속 시간·이징·색 토큰처럼 값 수준으로
   - 예상 수정 위치(파일)
   - 난이도(소·중·대)
3. **앱 전체 일관성 규칙 제안**: 모션 토큰, 버튼 위계와 배치, 모서리와 테두리, 호버·포커스·누름 상태, 토스트와 피드백. 기존 토큰(`Tokens.xaml`의 Motion.Fast·Normal·Deliberate 등)과 어떻게 맞출지 포함합니다.
4. **바로 고칠 것(1~2시간 이내)과 큰 개편**을 구분합니다.
5. **확인하지 못한 것**: 렌더 PNG로는 볼 수 없는 실제 애니메이션, 실기 DPI 등.

분량은 핵심 위주로 3,000단어 이내로 씁니다. 근거 없이 점수나 확률을 만들지 마십시오.
