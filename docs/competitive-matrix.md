# 경쟁 기준과 제품 방향 (2026-09)

이 문서는 홍보용 승리 선언이 아니라 **현재 구현과 다음 투자 순서를 구분하는 의사결정표**다.
경쟁 제품의 좋은 상호작용은 배우되, 코드·아이콘·문구를 복제하지 않고 공개 문서와 실제
MyCapture 코드/테스트를 근거로 독립 구현한다.

## 비교 근거

- [Snipaste 공식 Getting Started](https://github.com/Snipaste/feedback/wiki/Getting-Started):
  F3 붙이기, 확대·투명도·클릭 통과, 닫은 이미지 복구, 색/텍스트/파일 경로 붙이기.
- [알캡처 공식 제품 페이지](https://altools.co.kr/product/ALCAPTURE): 전체·스크롤·지정 크기
  캡처와 크롭·모자이크 등 현재 공개 기능.
- [ShareX 공식 가이드](https://getsharex.com/blog/guides/): 캡처 후 작업 파이프라인,
  업로드 자동화, FFmpeg 기반 영상·GIF·오디오 녹화.
- [ScreenToGif 공식 기능 페이지](https://www.screentogif.com/features): 프레임 타임라인 편집과
  GIF/APNG/영상 내보내기.
- [OBS Studio 공식 문서](https://obsproject.com/kb/): 다중 소스, 오디오, 스트리밍,
  하드웨어 인코딩 중심의 전문 녹화.
- [FFmpeg 공식 법률/라이선스 안내](https://ffmpeg.org/legal.html): 선택 빌드에 따라
  LGPL/GPL 의무가 달라지는 네이티브 공급망.

가격, 라이선스 등급과 기능은 바뀔 수 있으므로 출시 의사결정 전에는 위 1차 출처를 다시
확인한다. 알캡처는 공식 페이지에 명시된 기능만 비교하며 광고·번들 같은 확인되지 않은
주장은 사용하지 않는다.

## 1.6에서 추가로 흡수한 장점

1. **캡처와 화면 고정의 명시적 분리**
   - 영역 캡처는 편집기를 열고 원본을 클립보드에 복사하되 자동 플로팅 창을 만들지 않는다.
   - 참조 창이 필요할 때만 `F3`을 사용해 캡처마다 창을 닫아야 하는 방해를 없앤다.
2. **클립보드 내용의 의미를 보존하는 핀**
   - 일반 텍스트는 카드로, Excel 탭 구분 데이터는 빈 셀을 유지한 표로 렌더링한다.
   - Excel이 이미지 표현도 함께 제공할 때는 셀 구조를 가진 텍스트를 우선하고, 일반 이미지 항목은 기존 이미지 우선순위를 유지한다.
3. **보이는 이미지와 원문을 구분한 복사 계약**
   - `Ctrl+C`는 렌더링된 이미지를, `Ctrl+더블클릭`은 텍스트·표의 전체 Unicode 원문을 복사한다.
   - 화면 미리보기는 안전한 크기로 제한하지만 원문은 자르지 않고 핀 수명 동안 메모리에 보존한다.

## 1.3에서 추가로 흡수한 장점

1. **OS 캡처 도구의 자동 가리기를 넘어선 편집 가능성**
   - 로컬 OCR에서 이메일·한국 전화번호·주민번호 형태·Luhn 유효 카드·IPv4·주요 비밀 키를 보수적으로 탐지.
   - 탐지 출력에는 평문을 남기지 않고 좌표만 전달하며, 가림막은 일반 레이어여서 검토·이동·삭제·한 번에 Undo 가능.
2. **긴 녹화를 버리지 않는 종료 경계**
   - MP4 트레일러 확정을 dispatcher 밖에서 수행해 창을 계속 응답 가능하게 유지.
   - 확정 중 닫기를 막고, 이미 존재하는 사설 staging/publish-ready/startup recovery 계약으로 인계.
3. **SDK 없는 개발 PC의 재현 가능 빌드**
   - `global.json`의 정확한 SDK를 관리자 권한·레지스트리·사용자 PATH 변경 없이 설치하는 부트스트랩 제공.
   - 배포본은 계속 self-contained여서 최종 사용자에게 .NET 설치를 요구하지 않음.

## 1.1에서 흡수한 장점(역사 기록)

1. **Snipaste식 핀 생산성**
   - 우클릭 첫 항목으로 `다른 이름으로 저장…`과 `빠른 저장` 제공.
   - `Ctrl+Shift+S` / `Ctrl+S`를 제공하고, 확대된 화면이 아니라 frozen 원본 픽셀을 PNG로 저장.
   - PNG 클립보드 형식을 우선 읽어 알파를 보존하고 Bitmap을 호환 경로로 유지.
2. **작업을 끊지 않는 피드백**
   - 창·버튼·핀에 83/167/250ms 모션 토큰을 적용하고 Windows의 애니메이션 끄기 설정을 존중.
   - 클립보드 재시도의 `Thread.Sleep`과 큰 PNG 인코딩을 UI 스레드에서 제거.
3. **녹화 도구의 관찰 가능성**
   - 기본값을 30fps로 높이고 60fps 선택을 추가.
   - 예상/실제/드롭 프레임, 실효 FPS를 결과 로그와 편집기에서 확인.
4. **제로 구성 오프라인 실행**
   - FFmpeg를 무조건 번들하지 않고 Windows Media Foundation을 사용해 네이티브 다운로드,
     코덱 업데이트, GPL/LGPL 배포 표면을 피함.

새 래스터 에셋은 필요하지 않았다. 저장·저장 위치 선택 아이콘은 기존 토큰 기반 SVG/Geometry
리소스를 재사용했고, 부드러움은 이미지 장식이 아니라 상태 전환·스레딩·프레임 페이싱 문제로
해결했다.

## 오픈소스 활용 원칙

- 기본 플랫폼은 .NET/WPF, Windows Media Foundation, Windows OCR처럼 배포 계약이 명확한
  구성요소를 사용한다.
- permissive 라이선스(MIT/Apache/BSD)를 우선하고, 직접 의존성과 배포 런타임의 라이선스·고지를
  패키지에 포함한다.
- GPL 프로젝트(예: ShareX/OBS)의 **UX 원리와 공개 문서**는 연구할 수 있지만 코드는 섞지 않는다.
- FFmpeg는 기능상 필요할 때만 교체 가능한 선택 모듈로 평가한다. exact build commit, configure
  flags, DLL hash, SBOM, CVE 검사, LGPL/GPL 고지와 교체 가능성을 통과하기 전에는 포함하지 않는다.
- 새 네이티브 캡처 라이브러리는 라이선스뿐 아니라 Windows 11 하한, 멀티 DPI, 드라이버 복구,
  self-contained 패키징과 실제 장치 soak를 함께 통과해야 한다.

## 검증 규칙

- “구현” 표시는 코드 경로와 자동 테스트 또는 packaged self-test가 모두 있을 때만 사용한다.
- 응답성은 느낌만으로 합격시키지 않고 UI 스레드 stall, 녹화 실효 FPS/드롭률, 1080p/4K CPU를
  기록한다.
- 외부 라이브러리는 최신 버전이라는 이유만으로 채택하지 않는다. 취약점, 유지보수, 바이너리
  크기, 라이선스, 롤백 비용을 포함한 ADR을 먼저 작성한다.
- 아직 없는 기능은 공개 README와 릴리스 노트에 그대로 “미구현”으로 남긴다.
